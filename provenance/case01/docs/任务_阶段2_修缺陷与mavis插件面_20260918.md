## 3. 缺陷 A1(高):仓库根 `requirements.txt` 还钉在 1.0.0

事实:`D:\zzr\provenance\requirements.txt`(根)内容是 `mavisframework==1.0.0`,且没有 mavis-vizkit 行;
而 `D:\zzr\provenance\provenance\requirements.txt`(内层)才是 1.1.0 + mavis-vizkit。

为什么这是高优先级:`README.md` 的安装流程第 46 行先 `cd ../provenance`,第 52/58 行才
`pip install -r requirements.txt`——那一步 cwd 是**仓库根**,命中的是根文件。后果是:
① 第 51/57 行刚装好的 1.1.0 wheel 会被这个 pin 顶掉;
② `mavisframework==1.0.0` 不在 PyPI(自研框架),解析直接失败;
③ mavis-vizkit 不会被装上,`case01/vizkit` 薄壳与 CI 之外的本地环境都会 import 失败。

修法(建议,可按你的判断调整但要说明理由):把根文件改成单一来源的指针,内容只有注释 +
`-r provenance/requirements.txt`,并在注释里写清"平台依赖以内层为准"。这样
`pip install -r requirements.txt` 仍然可用且不会漂移。改完检查 README/README_zh 里所有
`requirements.txt` 的引用是否还有 cwd 歧义(英文版同样检查)。

验收(报告里贴命令与输出):

- 根文件里不再出现 `mavisframework==1.0.0`;
- `python -m pip install --dry-run -r requirements.txt`(或 `--report`)能解析到
  `mavisframework==1.1.0` 与 `mavis-vizkit==0.1.0`;若本机不联网装不了 mavisframework,
  至少证明嵌套 `-r` 被解析(把 `--dry-run` 的输出或 `-r` 展开结果贴出来),并说明哪一步没法离线验证。

## 5. 阶段 2:给 mavis 加通用插件面

目标:mavis 自己不认识任何具体插件,但要让**任何外部包**都能作为插件挂进来。
现状(已核实):mavis 里 `plugin` / `entry_point` / `importlib.metadata` 全空,没有插件机制;
唯一的注册表是 `Simulator.CONDITION_CHECKERS`(条件类型);回调是"构造时各传一个函数";
`chat_callback` 是进程级全局单例。

必须做到的六件事:

1. **插件接口**:`setup(ctx)` / `on_event(evt)` / `teardown()`,三个都可选实现(缺省 no-op)。
2. **注册与实例化**:必须能表达**带必传配置的插件**——这是阶段 1 暴露的真问题:
   现在 `create("town")` / `create("live")` / `create("report")` 都实例化不出来,
   所以"注册表 + 入口点发现"发现了也挂不上。
   推荐形态(你可以提更好的,但要说明为什么):调用方传**插件实例列表**(实例天然带配置);
   另外提供可选的按名注册表 + 入口点发现,组名 `mavisframework.plugins`,
   且发现只对"声明可无参构造"的插件生效。
3. **故障隔离**:一个插件抛异常不能让运行中断,要记 warning 并继续(参考 mavis-vizkit 的
   `Fanout` 的做法,但接口要通用、不含任何可视化/业务语义)。
4. **生命周期**:随 `Game` / `Simulator` 的创建与收尾调用;不传插件时**完全不介入**。
5. **事件总线**:把已有的协议事件(`init` / `time` / `agent` / `chat_line` / `story` / `snapshot`)
   广播给插件。**必须复用现有 `on_agent` / `on_step` / `on_story` 的同一份内部实现**,
   不要把逻辑复制一份,否则两套事件源迟早不一致。
6. **`chat_callback` 单例问题**:它现在同进程只能有一个消费者(provenance 实时服务与
   case01 vizkit 会互相顶掉,而且都不报错)。改成多订阅者,同时**保持旧写法仍然有效**
   (直接赋值 `agent_core.chat_callback = fn` 的行为不能破)。

硬约束(违反任意一条都算失败):

- 纯新增、默认关闭:不注册插件时,行为与现在**逐位一致**。
- 不改任何既有行为语义;不改现有函数签名,只允许加可选参数。
- 框架源码零业务词汇;`tests/test_extension_surface.py` 必须继续通过,并把新增的公开面
  **加进那份契约测试**(签名、默认值、默认不介入)。
- 全量测试保持绿:`D:\zzr\mavis` 全量 107 + 你新增的例;mavis-vizkit 25;case01 197;外层 23。
- **不要 bump 版本号、不要重建 `dist/`、不要 push 到 mavis `main`。**
  在 mavis 仓新建分支 `feat/plugin-surface`,提交在分支上即可;合并与版本号由验收后人工决定。
- 不要改 provenance 对 mavis 的依赖方式,也不要顺手改 mavis-vizkit 的结构。
- 不要为了让新面"看起来被用上"就把 vizkit 硬接进 mavis:mavis 不 import mavis-vizkit。
