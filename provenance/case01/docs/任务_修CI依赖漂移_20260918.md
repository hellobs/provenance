## 3. 缺陷:两条守卫测试在 CI 里必红(本轮要修)

**证据(我实测,不是推理):**

- `case01/tests/test_serve.py:175` 与 `:189` 在**函数体内** `import yaml`;
- `provenance/requirements.txt` 里**没有** `pyyaml`;
- `.github/workflows/ci.yml:29` 的安装清单是
  `pip install pytest fastapi uvicorn websockets jinja2 httpx`——**也没有 pyyaml**;
- CI 全程**不从 requirements 安装**,只装这个手维护清单。

**复现(照 CI 的步骤做一遍,我已实测):**

```
python3.12 -m venv <tmp>            # 或 uv venv --python 3.12
<tmp>/bin/pip install pytest fastapi uvicorn websockets jinja2 httpx
<tmp>/bin/pip install <mavis 克隆>   # 等价 CI 的 pip install ../mavis(非 editable)
<tmp>/bin/pip install -e packages/mavis-vizkit
cd provenance && <tmp>/bin/python -m pytest case01/tests -q
# 实测结果:2 failed, 205 passed
#   test_serve.py:175 ModuleNotFoundError: No module named 'yaml'
#   test_serve.py:189 ModuleNotFoundError: No module named 'yaml'
```

**为什么本地是绿的**:`.venv-live` 里恰好有 pyyaml(未声明,由别的包带进来),所以本地 207 passed。
**为什么 grep 抓不到**:`import yaml` 在函数体内而非模块级,只扫模块级 import 的检查看不见它——
**只有跑 CI 等价环境才能发现**。(这条我上一轮也没抓到:当时只在 `.venv-live` 里跑了套件,
责任同样在我;但必须修,否则 CI 一直是红的。)

把 `pyyaml` 加进 `provenance/requirements.txt`(内层),并注明用途
(OpenAPI 漂移守卫测试读 `docs/case01_api.openapi.yaml`)。

### B. 让 CI 的依赖只有一个来源(推荐)

把 `ci.yml` 的 "Install test dependencies" 改成从 `provenance/requirements.txt` 安装
(外加 `pytest`),而不是手维护清单。这样"测试用了未声明的依赖"在结构上不可能再发生。

requirements 保持同步"——但这只是约定,不如单一来源可靠)。

### C. 验收必须是 **CI 等价复现**(本轮的硬验收)

照 §3 的步骤,在一个**新建的 py3.12 venv** 里:装 CI 的依赖(或你改后的方式)→ 装 mavis
(克隆或本地,与 CI 一致用非 editable)→ 装 mavis-vizkit → 从 `provenance` 目录跑
`python -m pytest case01/tests -q`,**贴出完整的 `N passed` 汇总行**。
**不要只在 `.venv-live` 里跑**——那样验不出这个缺陷。

顺手也跑 CI 的另外两步:外层 `python -m pytest tests -v` 与
`node tests/frontend_smoke.js tests/_pages`,确认没有同类问题。
