## 3. 本轮要解决的真实缺口(本任务主体)

`case01/docs/case01_api.openapi.yaml` 是**给平台侧看的机器可读契约**,但它已经与实现和口径脱节:

1. **缺 `/viewer`**:`serve.py:61` 有 `app.mount("/viewer", ...)`(来自 引擎侧的 `7ae216f`,
   现已在分支里),而 YAML 只有 `/`、`/api/runs`、`/api/runs/{run_id}`、
   `/api/runs/{run_id}/full-context` 四条路径。
2. **响应体全是泛对象**:四条 200 响应都是 `additionalProperties: true` 的 `type: object`,
   对字段没有任何描述。于是本轮 B1/B2/B3 的三条口径(risk 枚举小写、issue 复合主键、
   顶层附加键平台不读)**只进了 prose 契约,机器可读规格里一个字都没有**——
   平台侧若按 YAML 生成客户端,拿不到这些信息。
3. **没有漂移守卫**:`test_serve.py` 的 `TestOpenApi` 只断言运行时 `/openapi.json` 含三个
   run 端点;没有任何测试把**静态 YAML 的 paths** 与 **`serve.app.routes` 的实际路径**绑起来,
   所以它能从 2026-09-05 静默过期到现在。

要求:

### A. `/viewer` 怎么处理

在你的判断下**二选一**,并把结论写进规格与理由:

- (a) 写进规格,并标注它是"引擎侧调试挂载,不是平台对接面";
- (b) 不写进规格,但在文件顶部注明"本文件只覆盖平台对接端点,不含 `/viewer`"。

注意 prose 契约现在说 5001 不在冻结契约内,而 `/viewer` 挂在 **5002** 上——
写理由时要把这一层说清。

### B. 补结构化 schema

至少覆盖:

- `/api/runs` 与 `/api/runs/{run_id}` 的响应:明确顶层键里哪些是平台**要读**的
  (`run_id` / 日期 / `turns` / `retrievals` / `events` / `state_history` /
  `final_feedback` / `audit` / `condition_monitor` / `reflection` / `router`),
  哪些是引擎侧附加键、**平台不读**(`summary` / `injector` / `compat`,并写明 `injector`
  含 Branch 实验元信息,不得进专家视图)。
- `router.issues[]` 的字段:`id` / `summary` / `field` / `risk` / `routing_reason`,
  其中 `risk` 的 `enum` 必须是 `[low, medium, high]`,并在描述里写清
  `id` 是 run 内序号、平台主键是 `(run_id, issue_id)`。
- `/api/runs/{run_id}/full-context` 的响应:说明它是自然语言全文、不含实验元信息。

两种做法任选,但要说明取舍:

- ① **在 YAML 里手写 schema**(纯文档改动、低风险,**推荐**);
- ② 给 `serve.py` 加响应模型(会改变运行时 `/openapi.json`,必须同步 `test_serve.py` 的断言,
  影响面更大)。若选 ②,把影响面写清楚。

### C. 漂移守卫测试(必须)

在 `case01/tests/test_serve.py` 增加一条断言:**静态 YAML 的 `paths` 集合 ==
`serve.app.routes` 的实际路径集合**(排序后比较)。允许显式排除项(例如你判定不写进规格的
`/viewer`、以及 FastAPI 自带的 `/docs`、`/openapi.json`、`/redoc`),但**每一条排除都必须在
测试里写明为什么排除**,否则守卫会变成摆设。

### D. 若 YAML 里写了 risk 枚举,再加一条断言

断言 YAML 里的 `risk` enum 与代码的 `_ROUTER_RISKS`(从 `case01.reflection` 导入)**一致**,
避免"契约写的枚举"和"代码归一化的枚举"两处各自漂移。
