## 一、数据流(上游已存在,本次补齐中游)

```
专家标记 (POST 5010 /api/reflections/mark)
  → live/reflections.py: reflection_marks.json(+JSONL 导出)
  → build_lora_sample(): SFT {instruction,input,output} + DPO {prompt,chosen,rejected}
  → case01/tools/lora_prep.py --export        ← 本次新增
      校验门:非空/长度≥20/无客套·追问·emoji(与反思管线同门)/verdict 枚举/
             incorrect·partial 必须有 correction/chosen≠rejected/内容去重(sha)
      产物:results/lora/{sft,dpo}.jsonl + dataset_report.json(含拒绝原因分布)
```

**现状基线**:`--export` 实测 0 条标记 → 空 JSONL + 报告,管道不炸(预准备完成度的
验证方式)。schema 端到端验证用 `--synthetic`(3 条合成标记 → 3 SFT + 2 DPO,
0 不合格;产物存档 `results/lora/_synthetic/` 作 schema 样例)。

## 三、标记到达后的 Runbook(5 步)

1. 专家经 5010 面板/接口打标(POST /api/reflections/mark,verdict ∈
   correct/incorrect/partial,incorrect·partial 必填 correction);
2. `python -m case01.tools.lora_prep --export` → 看 `dataset_report.json` 的
   拒绝原因分布(校验门把不合格样本挡在训练外,拒绝要逐条过目);
3. `--validate` 两个 JSONL 复核;**数据量下限**:SFT ≥ 50、DPO ≥ 20 之前不建议开训
   (小样本 LoRA 易过拟合到措辞);
4. 装训练栈(--env 体检转绿)→ QLoRA 配置起点:r=16, alpha=32, dropout=0.05,
   目标模块 q/k/v/o + gate/up/down,lr 1e-4 cosine,2-3 epoch;
5. 产物接入:merge 后转 GGUF → `ollama create <model> -f Modelfile`,或 Ollama
   直接挂 adapter;**上线前必须过回归**:case01 的冲突检测/一致性戳/反思质量门
   照常跑,并用 `router_sensitivity` 的思路对比微调前后行为。

## 四、设计取舍(为什么不做什么)

- **不用 verdict=correct 的样本学"对齐方向"**:correct 样本的 output=原反思,
  SFT 只教格式与风格;对齐方向在 DPO 的 chosen/rejected 对里。训练配比要按此设计;
- **不从 24 条成品反思造自模仿 SFT**:那是在教模型模仿自己,零新信息;
- **数据侧不引入训练依赖**:lora_prep 只用运行时环境即可跑(校验门 import 失败
  时优雅降级为纯结构校验);
- LoRA 训练脚本本体**不在本次预准备范围**(无 CUDA 环境写了也无法验证,写了就是
  不可测代码);环境转绿后按 Runbook 第 4 步补。
