## 一、数据流(上游已存在,本次补齐中游)

```
专家标记 (POST 5010 /api/reflections/mark)
  → live/reflections.py: reflection_marks.json(+JSONL 导出)
  → build_lora_sample(): SFT {instruction,input,output} + DPO {prompt,chosen,rejected}
  → case01/tools/lora_prep.py --export        ← 本次新增
      校验门:非空/长度≥20/无客套·追问·emoji(与反思管线同门)/verdict 枚举/
             incorrect·partial 必须有 correction/chosen≠rejected/内容去重(sha)
      产物:results/lora/{sft,dpo}.jsonl + dataset_report.json(含拒绝原因分布)
```

**现状基线**:`--export` 实测 0 条标记 → 空 JSONL + 报告,管道不炸(预准备完成度的
验证方式)。schema 端到端验证用 `--synthetic`(3 条合成标记 → 3 SFT + 2 DPO,
0 不合格;产物存档 `results/lora/_synthetic/` 作 schema 样例)。

## 三、标记到达后的 Runbook(5 步)

1. 专家打标。**两条入口,同一道判定门**:
   - 审核面板 `http://127.0.0.1:5010/review/expert`(平台词 approve/edit/reject,
     服务端映射 + 落 `review` 块:run_id/issue_id/专业/anchor/版本)—— 参照实现见
     `case01/expert_review_app.py`,字段口径见 `docs/给平台侧_专家意见字段与训练线映射.md`;
   - 或 `POST /api/reflections/mark`(本平台词 correct/incorrect/partial,
     incorrect·partial 必填 correction)。
2. `python -m case01.tools.lora_prep --export` → 看 `dataset_report.json` 的
   拒绝原因分布(校验门把不合格样本挡在训练外,拒绝要逐条过目)。
   **2026-10-07 22:0x 全链实测 → 23:2x 订正**:面板提交 1 条 → 库里 3 条 → 导出 `sft:1 / dpo:0 /
   rejected:2`,那 2 条被拒的是 2026-09-27 的边界探针(`agent="x"`,其中一条 thought 是
   10 万字重复串)—— 它们当时没有 `origin` 键,按 expert 读就被当训练样本收了
   (`input_max` 一度是 100025)。已按既有语义补标 `origin="probe"` 后重导,读数回到
   1937/1912 字。**教训:"库里几条"不等于"能训几条",每次导出都要读 `reject_reasons`。**
   ⚠ **而那句"面板提交 1 条"当场就被我自己撤回过**(23:2x):那 1 条是**我自己点面板联调**
   留下的,而 `/api/expert/decision` 是专家通道、把任何提交都写成 `origin=expert`,
   所以它当时**真的以"专家意见"的身份进了池**。已照实改标 `origin=probe`
   (标记文件在 `data/ledgers/`(2026-10-08 起跨局台账的家;原 `provenance/results/checkpoints/` 已无文件),不入 git;`.bak` 备份在 `data/ledgers/_bak/`),重导后
   `marks:3 / sft:0 / dpo:0 / rejected:3`。⇒ **本管线至今没有任何可训样本**;
   链路口径"通"只指"机制通",不指"有真信号"。自测即探针,别当专家意见引用。
3. `--validate` 两个 JSONL 复核;**数据量下限**:SFT ≥ 50、DPO ≥ 20 之前不建议开训
   (小样本 LoRA 易过拟合到措辞)。⚠ 这个数**不能按"标记总数"去凑**:DPO 对只从
   `verdict ∈ incorrect/partial` 且 `correction` 非空的标记生成,`correct` 一条也不产
   ⇒ 收数要求要写成"≥50 份判定,**其中 ≥20 份带最终改文**"。另:DPO 还要求 `chosen`
   与 `rejected` 同量纲(片段改文 vs 整篇反思不成对,判据见映射文档 §三·补 ①),
   段级改文必须先有 `anchor` 定位才能回填成完整反思;
4. 装训练栈(--env 体检转绿)→ QLoRA 配置起点:r=16, alpha=32, dropout=0.05,
   目标模块 q/k/v/o + gate/up/down,lr 1e-4 cosine,2-3 epoch;
   ⚠ **`seq` 按下限 ≥2048 起,不要沿用先前写的 1024**:2026-10-07 实测真实反思
   1591–3387 字,而 SFT 样本的 `input` = 前缀 + 整篇反思(实测 1616–3412 字),
   1024 必截断,而反思质量扣分集中在**尾部几维**(经验迁移/不确定性/过程),
   截断恰好切掉信号。读数现在在 `dataset_report.json` 的 `stats.char_len` 里,照它定;
5. 产物接入:merge 后转 GGUF → `ollama create <model> -f Modelfile`,或 Ollama
   直接挂 adapter;**上线前必须过回归**:case01 的冲突检测/一致性戳/反思质量门
   照常跑,并用 `router_sensitivity` 的思路对比微调前后行为。

## 四、设计取舍(为什么不做什么)

- **不用 verdict=correct 的样本学"对齐方向"**:correct 样本的 output=原反思,
  SFT 只教格式与风格;对齐方向在 DPO 的 chosen/rejected 对里。训练配比要按此设计;
- **不从 24 条成品反思造自模仿 SFT**:那是在教模型模仿自己,零新信息;
- **模拟/回填/探针的意见不进训练集**(2026-10-07 加,同日补 `probe`):`origin != expert`
  一律拒收并记原因。`origin` 取值 `expert / simulated / backfilled / probe`;缺键按
  `expert` 读,所以**历史行要显式补标**(9-27 那两条边界探针就是这么混进 `--export` 的)。
  必要性是实测的——用 4b 扮专家造的 4 条标记,旧校验门 `sft:4/dpo:4/rejected:0` 全放过,
  逐字节分不出真假;判据与数字见 `docs/给平台侧_专家意见字段与训练线映射.md` §三·补;
- **数据侧不引入训练依赖**:lora_prep 只用运行时环境即可跑(校验门 import 失败
  时优雅降级为纯结构校验);
- LoRA 训练脚本本体**不在本次预准备范围**(无 CUDA 环境写了也无法验证,写了就是
  不可测代码);环境转绿后按 Runbook 第 4 步补。
