## 4. 任务 B(主体):引擎侧对平台契约的口径修正

背景:平台侧体检(见转接文档 §11)发现引擎对外契约里有几处口径与实现不一致或缺失。
这些是**引擎侧该修的**,不需要等 mavis 合并。所有结论都要有实测依据。

### B1. `risk` 枚举口径不一致(中)

`case01/docs/Governance平台对接说明.md:62` 写的是 `risk`(Low / Medium / High)。
实测六份记录全部是**小写**:`demo-1` / `demo-2` / `demo-3`(旧引擎)与
`demo-A-mavis` / `demo-B-mavis` / `demo-C-mavis` 的 `router.issues[].risk` 都是
`high` / `medium` / `low`。
要求:在契约里把取值写准(以小写为准),或明确写"以小写为准、平台侧比较时忽略大小写";
并注明这条结论的来源与核对日期。**不要**为了迁就文档去改记录。

### B2. issue 主键口径缺失(中)

`router.issues[].id` 是 **run 内序号**(`issue-1`..`issue-N`),跨 run 会重名。
要求:在契约里写死平台侧建单/幂等的主键为 `(run_id, issue_id)`,并说明若不这样会出现什么错配
(不同 run 的 issue-1 被当成同一条任务)。给出实测依据(同一份记录里 id 形如 `issue-N`,
不同 run 都有 `issue-1`)。

### B3. 顶层多出键未标注"平台不读",且专家视图泄漏风险未设防(中)

实测 case01 记录的顶层键比契约多出 `summary` / `injector` / `compat`,契约里没有说明。
其中 `injector` 段含 Branch 实验元信息与 dialogue,**绝不能进专家视图**。
要求:

1. 契约里补一段:明确 `summary` / `injector` / `compat` 是引擎侧附加键、**平台不读**;
   并写明 `injector` 属实验元信息,不得进专家面向的任何展示。
2. 扩展专家视图的泄漏测试:`case01/tests/test_full_context.py:72` 现有禁止清单是
   `("Branch A", "Branch B", "Branch C", "branch_action", ...)`,请把
   `injector` / `compat` 以及 injector 段里的字段名(如 `nodes` / `context` / `agents`)
   一并纳入,并**实际跑通**(若某条断言因为纯文字巧合而误伤——例如正文里本来就会出现
   "nodes" 之外的词——就把清单收敛到真正表示元信息的字符串,并在报告里说明取舍)。
