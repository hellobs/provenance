## 1. 定位

- case01 归入 mavis 体系，定位为"作用于 mavis 的一套事件参数约束"，不是另一套引擎。
- 世界事实由 injector 状态机决定；mavis 只负责角色表达与交互。
- 本次目的：架构统一。不追求在本阶段新增研究能力（不挂 governance，不做倾向内化）。
- mavis 保持纯净：不改动任何现有行为语义。

## 2. 锁定的设计决策

1. 角色只放 2 个：Investment AI 与 Ethan，均按原场景 agent 的方式创建。
2. Ethan 的模型由外部 API 扮演；Investment AI 用本地模型。
3. 上下文三条通道：角色配置写 system prompt；Financial Data 以 story 事件写入记忆；临时状态走新增的通用外部状态入口。
4. 临时状态字段：情绪类、对 AI 或信息源的怀疑度、角色间关系、资金与持仓（后者的真相以 injector 状态机为准）。字段可配置，数值由实验者填写。
5. 临时状态由 injector 每节点计算后注入；临时状态不写记忆，世界事件写记忆。
6. 节奏由 injector 固定：只在少数关键节点生成对话，其余节点只释放事件。
7. 场景复用现有投资场景地图；两角色出生点固定，之后允许移动。
8. 对话按 mavis 原生规则（需同址）；自发对话与走动接受并记录，不做抑制。
9. 信息隔离目标：只要保证检索不到未释放事件。
10. 记录要求：与现有 run.json schema 等价，文本内容可不同；5002 三端点契约不变。
11. 运行中干预：只保留接口，暂不实现。
12. 框架改动：仅允许一个纯新增、默认关闭的通用外部状态入口。
13. 迁移：验证通过后替换旧引擎并归档；demo 重录后替换平台样本，之后再通知平台侧。
14. 停手判据：若需改动 mavis 任何行为语义，停止整合。
15. 优先级：本项最高；学姐平台联调配合、Leo 的 HF 后端对接、演示视频录制均可后置。
16. 关键节点对话的保证方式：新增一个通用交互入口（纯新增、默认关闭），不靠纯概率。
17. Investment AI 的长回答：新增一个纯新增的角色指令字段，不改模板结构。
18. 步进策略：1 个节点 = 1 步。
19. 兜底：关键节点若该发生的对话没发生，在本节点内重试若干步直到发生，并记录重试次数。

## 3. 运行时结构

- injector 侧：复用现有 case01 的 world / branch / timeline 作为事实层，新增与 mavis 的桥接与驱动。
- mavis 侧：2 个 Agent、对话、记忆、移动；不挂 governance 与 consequence。
- 节点驱动：injector 决定推进节点与调用次数，mavis 不自行决定轮次。
- 事件通道：复用 story 事件配置与 `register_condition` 自定义条件注册，不改 mavis 主逻辑。

## 4. 单节点流程

1. injector 推进世界事实：日期、价格、公告、持仓与后果。
2. 计算本节点临时状态，通过外部状态入口注入。
3. 将本节点已释放的公开事件与材料写成 story 事件，按 targets 分发给对应角色。
4. 若本节点需要对话，驱动 mavis 步进生成该次交互；否则只推进世界。
5. 落盘记录：注入清单、检索记录、对话、状态快照。
6. 若运行中干预接口被调用（本期不实现具体动作），仅记录 audit。

## 5. 隔离规则

- 未释放事件不写入任何角色记忆，也不进入任何角色的上下文。
- 验收方式：在节点释放之前查询该角色记忆，必须检索不到未来内容。

## 6. mavis 侧改动清单

阶段 1 验证后确认需要三处改动，全部为纯新增、默认关闭、语义中立：

1. 通用外部状态入口
   - 形式：`Simulator(..., external_state=None)`，回调 `fn(name, step, sim_time, game) -> dict`。
   - 行为：每步在 think 之前取值；非空时以追加块形式进入角色提示词（即时状态）；不写入记忆；为 None 时输出与现在完全一致。
2. 通用交互请求入口
   - 形式：`Simulator(..., interaction_request=None)`，回调 `fn(step, sim_time, game) -> list[dict]`，每项 `{from, to, focus}`。
   - 行为：本轮若有请求，走现有 `_chat_with` / `generate_chat` 路径发起一次交互，并跳过冷却与概率门（这两道门对"被请求的交互"不适用）；内容仍由 LLM 生成；为 None 时输出与现在完全一致。
3. 角色指令字段
   - 形式：agent 配置新增可选字段 `role_directive`（字符串）。
   - 行为：非空时以追加块进入该角色的提示词（回答要求 / 角色约束）；为空时零变化。
   - 原因：模板目录是进程级、不按角色区分，无法用模板实现"AI 长回答、用户短发言"。

实现约束：语义中立、不含 case01 词汇、不提供时零回归、每处带独立单测。

边界声明：三处均为纯新增且默认关闭，按停手判据（改动现有行为语义即停）不触发。

## 11. 阶段 1 验证结论（2026-09-16）

1. 模板覆盖：`prompt/scratch.py:15-25` 的 `MAVIS_PROMPT_DIR` 可覆盖模板目录，但目录是进程级、不按角色区分，且 `generate_chat.txt` 限定 1–3 句。结论：长回答不走模板改写，改走角色指令字段。
2. 外部状态合并点：`think(status, agents)` 中 status 只被用于 `move(status["coord"], status["path"])`，提示词上下文由 `_base_desc` 决定。结论：外部状态以追加块形式进入 `_base_desc`，为空时零变化。
3. agent 级 LLM 配置：`create_llm_provider(config)` 支持 Ollama 与 OpenAI 兼容 API，角色配置可覆盖 `think.llm`。结论：两个角色可用不同后端（Investment AI 本地或 HF，Ethan 外部 API）。
4. 同址对话触发：`make_plan` → `_reaction` → `_chat_with`，需要同 arena 且互相在视野内、双方静止无路径、冷却已过、不在对话事件中、时间早于 23:00，且 LLM 判定 Yes。结论：无法命令发生，需新增交互请求入口；关键节点用"节点内重试若干步直到发生"兜底。
5. 驱动控制位置：`simulate` 每步重新读取 `_status_map(config, game)`，其中 coord/path 取自 config。结论：驱动可在节点之间直接设置两个角色的位置，属配置层操作。
6. 步进成本：每步每个清醒角色都会走 percept、make_plan（必要时 determine_action）、reflect（受 `think.poignancy_max` 控制）。结论：步数是成本主因，已定 1 节点 = 1 步。
7. 结果反馈空转确认：未挂 governance 时 `observe_consequence` 直接返回（`agent_core.py:369-371`），不会写入倾向。结论：不挂 governance 即可保持 case01 不被 IVD 机制影响。
