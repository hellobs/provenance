## 分层

### 1. mavisframework（运行方式/框架核心，独立仓 hellobs/mavis）
- 事件驱动的角色模拟内核：`Simulator`、`agent_core`、`Game`/`Timer`/`config.loader`。
- 插件面（1.2.0 起）：`mavisframework.plugin.Plugin`，`Simulator(plugins=[...])` 挂载。
- 三处默认关闭的注入钩子：`external_state` / `interaction_request` / `role_directive`。
- case01 与可视化都消费它的公开 API；它不反向依赖任何上层。

### 2. mavis-vizkit（可视化插件集，`packages/mavis-vizkit`，独立包）
- 消费 mavis 事件字典契约，提供 `events`（`init_event`/`story_event`/`chat_event` 等）与 `Fanout`/`create`。
- 独立版本化，被 case01 的 bridge 与前端 `live_fastapi` 引用。

### 3. case01（作用于 mavis 的一套事件参数约束 + 注入器，provenance 内模块）
- `bridge.py`：把 case01 挂到 mavis 上——改写消息渲染、装 `Simulator(plugins=[VizForwarder])`；
  依赖 mavis 框架与 mavis-vizkit。
- `world/`（state/timelines/branch）：事实层与市场时间线，纯净、不依赖 mavis。
- `injector/`（nodes/bridge/pipeline/record/worldfacts/conditions/viz_plugin/run_injector）：
  构造节点序列、推动咨询流程、产生「可回放」的 `run.json` 记录。
- `reflection.py`（8 维反思）与 `router`：运行后生成专家可审的反思与问题分流。
- `record.py` 的 `to_case01_record`：把注入器节点记录映射为 `run.json`（顶层键对照
  `CASE01_TOP_KEYS`）。

### 4. provenance 平台侧（对外/治理面）
- `serve.py` + `full_context.py`：治理平台只读服务与 OpenAPI 固定契约（5002）。
- `render.py` / `viz.py`：审查页与可视化输出。
- `vizkit/live_run.py`、`tools/isolation_probe.py`：业务别名与验证工具，都只
  `from ..injector.bridge/nodes` 引入。

## 依赖方向（单向）
```
mavis-vizkit ─┐
              ├──>  provenance 平台侧（live/治理/渲染）
mavisframework ┤
              └──>  case01（bridge 挂在插件面）──>  run.json → 平台侧
```

## 数据/控制流（简要）
- mavis 负责角色表达与交互；case01 用注入钩子在节点边界注入事实、把当前节点 story 事件
  释放进角色记忆，`bridge` 把事件改写成案例视图所需的消息。
- 一次 run 的产物：`run.json`（含 turns/retrievals/events/state_history/final_feedback/
  audit/reflection/router/injector），是平台侧只读消费的单一事实源。
- 专家侧通过 `full_context` 生成自然语言全文审核，不直接看 JSON。
