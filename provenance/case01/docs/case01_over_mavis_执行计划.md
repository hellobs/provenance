## 阶段 1：四个技术前提验证 —— 已完成（2026-09-16）

结论与接口签名见设计说明 §6 与 §11，摘要：

- 模板覆盖可用，但目录是进程级、不按角色区分，`generate_chat.txt` 限定 1–3 句 → 长回答改走"角色指令字段"。
- 外部状态需以追加块进入 `_base_desc`，为空时零变化。
- 两个角色可用不同 LLM 后端（agent 级配置即可）。
- 同址对话无法命令发生，需要的门槛有五个（同 arena、双方静止、冷却已过、不在对话中、LLM 判定 Yes）→ 新增通用交互请求入口，关键节点用"节点内重试直到发生"兜底。
- 驱动可在节点间直接设置两角色 coord（config 层），无需改代码。
- 步数是成本主因（每步每角色走 percept / make_plan / reflect）→ 已定 1 节点 = 1 步。
- 未挂 governance 时 `observe_consequence` 空转，case01 不受 IVD 机制影响。

据此确定的 mavis 侧改动为三处纯新增、默认关闭（设计说明 §6）：外部状态入口、交互请求入口、`role_directive` 字段。已用到三处，若还需第四处，先停下来复审。

## 风险与缓解

1. 节点对话时序不可控（最高风险）：阶段 1 第 4 项先验证；不成立则接受时序不完全受控，或按停手规则停。
2. 记录等价做不到：先在阶段 2 冻结 schema 对比脚本，早发现早调整。
3. 迁移期间 main 仍有他人改动：main 已开保护；迁移在独立分支进行。
4. 历史可比性被破坏：模型身份字段与 embedding 变更必须记录，避免与旧 run 混用。
5. 排期冲突：学姐平台联调配合、Leo 的 HF 后端、演示视频录制均已确认可后置。
