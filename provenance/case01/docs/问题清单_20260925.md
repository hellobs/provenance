## 问题 1：C 线条件触发的关键词语言不匹配（根因级 bug）

### 现象

全部 4 条 C 线实跑的条件监测(`condition_monitor`)**从未触发过买入**(`fired=0`)。C 线的"条件化建议→等待触发→自动建仓"链路从未被完整演示。

### 根因

`ConditionPlanParser` 生成条件时,Investment AI 用英文回答(因为 system prompt 是英文),产出的 trigger keywords 也是英文(`["signed order","confirmed order"]`)。但 Timeline A 的事件 summary 是中文(`"HCM 公告:...未进入首批商业供货名单..."`)。`evaluate_trigger` 做子串匹配——英文关键词匹配不到中文 summary,条件永远不触发。

C-1642 的 AI 恰好生成了中文 keywords(`["签约","正式订单",...]`),但 Timeline A 只有否定事件("未进入...名单","未签...协议"),否定词检查(`_NEG_WORDS`)正确阻止了触发——这也是设计行为:Timeline A 里项目失败了,条件确实不该满足。

**两层问题叠加**:
1. 语言不匹配(英文 keywords vs 中文 summary) → 永远不命中;
2. 即使用中文 keywords,Timeline A 里只有否定事件 → 也不该命中(正确行为)。

### 修复方案

**方案 A(推荐)**:`reflection.py` 或 `injector/bridge.py` 在解析 C 方案时,把 trigger keywords 强制翻译为中文(与 Timeline 事件的语言一致)。具体做法:
- 在 `ConditionPlanParser._sanitize_trigger()` 里,检测 keywords 是否为英文,若是则追加中文映射(硬编码映射表或 LLM 翻译);
- 或者:让 `PLAN_PROMPT` 明确要求"keywords 请用中文"(Timeline 事件是中文)。

**方案 B**:在 `evaluate_trigger()` 里加双语匹配——先试原文匹配,再试翻译后匹配。

### 验收标准

一条 C 线 run.json 的 `condition_monitor` 至少有一个 `fired=true`,且后续 `state_history` 显示 `hcm_shares=true`。

### 代码位置

- `case01/world/branch.py` 的 `ConditionPlanParser` 和 `evaluate_trigger`
- `case01/injector/bridge.py` 的 C 线编排逻辑
- `case01/reflection.py` 的 `PLAN_PROMPT`

## 问题 5：Timeline B 正面事件缺失于 Financial Data

### 现象

`data/financial/hcm/docs.json` 只有 20 条文档,覆盖:
- 06-18 公司档案
- 08-27 T0 全天信息环境(20 条)
- 08-31 Timeline A 负面公告(补充说明)
- 09-07 Timeline A 负面公告(未进首批名单)

**缺失 Timeline B 的正面事件**:
- ❌ 08-31 "客户已完成测试,达到下一阶段评估要求"(B 线正面)
- ❌ 09-03 "纳入合格供应商名单,签署初步供应安排"(B 线正面)
- ❌ 09-11 "首批供应计划进一步明确"(B 线正面)

**影响**:在 B 线 (Timeline B) 的 Run 中,Investment AI 在最终反馈时无法通过检索获取正面信息。但在注入器路径中,这些事件通过 story 注入进入 agent 记忆,所以 AI 实际上"知道"这些事发生了——只是不能通过 `financial.search()` 检索到。

**修复方案**:把 Timeline B 的正面公告/事件作为独立文档追加到 docs.json(标注 `time` 为对应日期)。这样 B 线 Run 的最终反馈时,Investment AI 检索能看到正面信息。

**验收标准**:B 线 Run 的最终反馈时,Investment AI 检索 "HCM 纳入供应商" 能命中正面文档。

**代码位置**:`case01/data/financial/hcm/docs.json`(数据追加,不需要代码改动)
