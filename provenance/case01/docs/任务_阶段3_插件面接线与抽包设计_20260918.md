  第 32 行列了 `Simulator(..., external_state=, interaction_request=, on_agent=, on_step=, on_story=)`,
  第 34 行写的是"process-wide `agent_core.chat_callback`"。
- `D:\zzr\mavis\README_zh.md` 第 23 行起 `## 📌 扩展面(与接入方的合同)`,第 28-29 行同样的清单。

并把 `chat_callback` 那句改成"老写法仍有效 + 新增多订阅"(别再说成只能一个消费者)。中英两份都要改。

### A2. agent 事件与 `protocol.AgentState` 不一致,而 docstring 声称"复用 protocol 键名"(中)

`mavisframework/plugin.py` 第 12 行写"事件字典复用 mavisframework.runtime.protocol 的键名"。
实测发出去的 `agent` 事件是 `type/name/coord/path/time/state`,而 `runtime/protocol.py:15-29` 的
`AgentState` 还定义了 `action / location / currently / conversation / role_type / goal_score /
goal_alignment / value_tendency`。`time` / `chat_line` / `story` 三种确实吻合,只有 `agent` 是
"框架原生子集 + 协议外的 `state`"。

要求的修法:**改文档,不要把转换塞进框架**。在 `plugin.py` 的模块 docstring 与
`tutorial-extension.md` §8 里写明:插件总线上 `time/chat_line/story` 与 protocol 一致;
`agent` 事件是框架原生子集(带 `name/coord/path/time` 与原始 `state`),
协议要求的 `action`(字符串)等字段由消费方自行映射——理由:在框架里做这层转换等于把
mavis-vizkit `events.as_text()` 那套复制一份,违反"不复制实现"的原始要求。

### A3. 插件拿到的是活引用(低-中)

`simulator.py` 的 agent 事件里 `state` 就是 `config["agents"][name]` 本身(后续步骤还会 `update()`);
story 事件的 dict 与 `on_story` 回调共用同一对象。插件若修改会污染运行状态,若长期持有会看到后续变化。

二选一,选哪个都要落地并在文档里写明:①在 tutorial §8 与 `plugin.py` 里标注"事件内容只读、
framework 可能继续改动其中的 dict";②story 事件传浅拷贝、agent 事件里的 `state` 保持原样但明确标注。
若选②加一条测试。不要为此改动事件类型或字段名。

### A4(可选,一句说明即可)

`on_story` 的守卫从 `if self.on_story:` 变成了 `if self.on_story is not None or self._pmgr:`,
