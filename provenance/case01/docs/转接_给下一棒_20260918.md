## 14. 铁律：不允许静默（2026-09-19 用户明确要求）

用户原话：**"很多东西就不应该静默处理"**。这条高于"代码好看/日志干净"：

### 14.1 触发它的真实事故

用户在浏览器里看实时可视化，反馈**"左边那个可视化里面的人根本没反应"**。

页面上、日志里都没有任何一句话解释"已经跑完了"。
同一类问题在 case00 的 5001 上也存在（`done` 只在结束时广播一次，晚到的人收不到）。

**结论**：这不是"少个提示"，是"把一次正常结束伪装成了故障"。

### 14.2 本轮改了什么

- `packages/mavis-vizkit/src/mavis_vizkit/plugins/live.py`
  - 新增 `finish(reason)`：广播 `{"type":"done","reason":...}` 并记住状态；
    新增只读属性 `finished` / `finish_reason`。
  - WS 握手顺序固定为：`init` → 追赶快照 → 未送达的积压事件 → **若已结束则立刻补一条 `done`**。
  - 追赶快照 `catch_up()`：有真实 `snapshot` 用它；没有就用"每个角色最近一条状态"**合成**
    （`{"synthesized": true}`），保证晚到/跑完后打开页面的人也能看到角色归位，而不是空小镇。
  - 模拟时间改为"**任何**带 `time` 的消息都记"（原来只认 `time`/`snapshot` 两类事件），
    否则"只跑出 agent 就中断"的运行合成快照时时间是空的。

## 15. 实跑自动映射 + 遗留产物标注（2026-09-19，用户拍板）

### 15.1 实跑跑完自动映射（已实现）

问题：`--start case01` 只落一份 `raw.json`，要在 5002/5004 上看到记录还得**手工**再跑一次

现在的行为：`live_switch.py --start case01` 在实时面起好后，再起一个**脱离的看护进程**
`case01/tools/map_after_run.py`，它

1. 轮询等 `raw.json` 出现（推演跑完 `bridge.save` 才写）；

### 16.2 为什么九块没有写进 mavis-vizkit

`mavis-vizkit` 必须保持零业务词（`case01` / 反思 / 问题分流 / 注入器 都是业务词，

`extra_tabs=[{"id","label","url"}]`（默认空 = 行为与以前完全一致），包只负责渲染页签并
嵌调用方给的 URL；**九块仍然留在 case01 侧**，由 case01 把它们挂到同一个服务上。

### 16.3 `--review-only`：不推演也能翻记录

5004 原来还有个作用——**任何时刻都能翻成品记录**（只读、不跑模拟）。这个作用不能丢，
所以 5010 多了一个不推演的模式：

```
python live_switch.py --start case01 --review-only
```

它只起界面、`live.finish("review_only")`（页面状态点显示"仅审阅模式"，不会让人对着
空小镇猜），不占 Ollama。配套改了三处：

- `live_switch.py --status` 现在分清 case01 的三种状态：**在推演 / 在听(已跑完) /
  仅审阅(未在推演)**——靠实时插件新报出的 `/health` 的 `finished`/`finish_reason`，
  不再靠猜（这是 §14 那条"分不清还在跑还是跑完在保持"的正解）；
- `--start case00` **不会**误停一个只处于"仅审阅"的 5010（它不抢 Ollama，而且是看结果的
  唯一界面）；
- 面板本身会在"正在实跑、但还没成品记录"时写一句提示（`/api/review/runs` 带
  `current_run_id`）——否则人会以为这次实跑的结果丢了。

### 16.4 顺带修掉一个会误报的坑（编码）

`map_after_run.py` 的看护进程输出重定向到文件时，stdout 用的是本地编码（中文 Windows 是
GBK），**打出对勾/叉号那类符号会抛 `UnicodeEncodeError`**——而它发生在映射**成功之后**，
于是日志里"成功"被写成"崩了"（2026-09-19 实测：记录确实生成了，收尾那行报错、退出码 1）。
现在：保留本地编码（不把中文变乱码）、只把打不出的字符替换掉，日志标记一律用 ASCII
的 `[ok]` / `[失败]`。`live_switch.py` 的 `[!] 有 N 个实例` 也是同一处理。
