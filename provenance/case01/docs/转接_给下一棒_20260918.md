### 14.2 本轮改了什么

- `packages/mavis-vizkit/src/mavis_vizkit/plugins/live.py`
  - 新增 `finish(reason)`：广播 `{"type":"done","reason":...}` 并记住状态；

  - WS 握手顺序固定为：`init` → 追赶快照 → 未送达的积压事件 → **若已结束则立刻补一条 `done`**。

## 18. 小镇与结果**同步**：实时记录（2026-09-19 用户："让可视化界面和结果界面能够同步，让我看一下全程"）

### 18.1 做法（为什么这么简单）

实跑与 HTTP 服务**本来就在同一个进程**里（uvicorn 跑在 vizkit 插件的线程），
所以不需要在引擎线程里维护推送节奏：起服务的人注册一个**无参 provider**，
面板每 2 秒来取一次即可。

- `case01/review_app.py`
  - `set_live_provider(provider, run_id, total_nodes)` / `clear_live()`；
    `GET /api/review/live` → `{ok, live, run_id, done_nodes, total_nodes, record}`。
  - 实时记录走的是**与成品记录同一套映射** `to_case01_record(bridge.run_record())`，
    所以九块不用改一行代码就能直接渲染跑到一半的数据；`branch_summary` 也在这里补
    （与 5002 契约同源）。
  - `reflection` / `router` 实时阶段必然是空的——面板在这两块明写
    "在运行结束后生成:跑完会自动出现在这里"，不留空白。
- `case01/vizkit/live_run.py`：跑之前 `set_live_provider(lambda: bridge.run_record(), …)`，
  进程退出时 `clear_live()`。**跑完不立刻撤**：成品记录还要等自动映射（~1–2 分钟），
  这期间面板继续显示完整过程，映射完由面板自动切到成品那份（那时才有反思与问题分流）。
- 面板前端：下拉最上面多一条 `● 实时 ｜ <run_id>（N/M 节点）`，有实跑时**默认就选它**；
  2 秒轮询、重渲染时**保住滚动位置**（否则长表格每 2 秒被拉回顶部）；
  表头写 `● 实时 … N/M 节点 · 反思/问题分流跑完才有`。

实测（本机 5010，实跑 B 线）：跑到第 1 个节点时
`turns=3 / retrievals=1 / events=2 / audit=7 / states=1 / injector.nodes=1`，
小镇在左边动、右栏数字同步往上长。

## 21. "重开一局"按钮（2026-09-19 用户："应该要搞一个小按钮，推演结束后决定要不要重开"）

### 21.1 长什么样、怎么走

- 位置：5010 页面**左上角状态块**里，跑完（或出错）后才出现的小按钮 `#restart-btn`；
  点它 → `POST /control/restart` → 成功后页面自动刷新（新一局必须从零开始：
  空小镇、清空对话、新的实时记录；原地复用会把上一局的画面留在屏幕上）。
- 服务端：`mavis-vizkit` 的 live 插件多了一个**通用控制口子** `on_restart`（默认 None）：
  传了才挂 `POST /control/restart`，并在页面里渲染按钮（`can_restart` 进模板上下文）。
  回调跑在线程池里（重开是重活，不能堵事件循环），返回的 dict 原样回给页面；
  回调抛错就回 `{"ok": false, "error": ...}`，页面把原因写在按钮下面——**不许静默成功**。
- 驱动侧（`case01/vizkit/live_run.py`）：主循环从"跑一局就收工"改成**可重开**：
  `while True: 铸新 run_id → 建 bridge → 跑 → save raw → finish → 起本局映射看护 →
  等保持期结束**或**收到重开请求 → 关 bridge → 有请求就继续下一局`。
  - 保持期内用 `restart_flag.wait(hold)`：点了按钮就**不用等满保持期**；
  - 跑的中途点按钮也受理，只是要等这一局跑完；
  - 每局都 `_spawn_mapper(...)` 起一个 `map_after_run` 看护进程 —— 否则**第二局跑完没有成品记录**
    （`live_switch` 当初只给第一局起了看护），面板又会回到"一片空白没人解释"。
  - `--no-restart` 可关掉按钮。
- 结果面板：多了一个 5 秒**看门狗**（`startWatch()`）。原因：用户点重开后，新 run_id 的实时记录
  会出现在 `/api/review/live`，而面板这时正停在上一局的成品记录上、已经停止轮询——
  不主动看就会一直显示旧的那条。看门狗发现"新的一局"就切过去并弹绿条说明。
  用户手动挑旧记录时会记下当时那一局（`IGNORED_LIVE`），同一局不再被拉回实时，但新一局照切。

### 21.2 测试

- vizkit：注册回调才有按钮与路由（没注册 → 页面无按钮、路由 404）、回调返回原样透传、
  回调抛错如实回 `ok=false`、`/health` 报 `can_restart`、`begin_run()` 清掉"已结束"、
  `bridge.close(keep_visualizers=True)` 不关共享插件。
- 驱动侧重开循环靠真机验收（`--nodes 1` 起一局 → `POST /control/restart` → 查端口还在、
  run_id 换了、`/health` 回到 `finished=false`）。

### 21.3 真机验收时发现的三个坑（都已修）

1. **重开一局后整个界面消失**：`bridge.close()` 里的 `fanout.close()` 会把**跨局共享**的
   live 插件一起关掉（它是 HTTP 服务本身）→ 5010 不再监听。
   修：`MavisBridge.close(keep_visualizers=True)`，每局收尾只关 bridge 侧的东西，
   插件留到进程退出时再关。
2. **第二局从第一秒起就显示"已结束"**：插件的 `_finished` 在上一局 `finish()` 之后一直为 True，
   新一局不清就会立刻给页面发 `done`。修：加 `LiveVisualizer.begin_run()`，每局开跑前清状态。
3. **连点"重开"会把映射进程堆起来抢 Ollama**：原来每局起一个 `map_after_run` 看护进程，
   点三次就有三个映射同时跑（实测），新一局的推演跟着变慢。
   修：映射改由实时面进程**顺序做**（`_map_run()`，跑完当刻映射），
   `live_switch` 不再另起看护进程（`_start_mapper` 停用保留说明）；
   `case01/tools/map_after_run.py` 仍留着供手工/离线映射。

## 22. 换场景（Tiled → 平台）一条命令（2026-09-19 晚）

用户在 Tiled 里做场景（`frontend/static/assets/village/tilemap/tilemap2.tmx`），
要装进平台得同时动三样，漏一样就出现"画面是新的、人却穿墙/卡住"：

1. `tilemap.json`（Phaser 渲染用的 Tiled 导出）；
2. `maze.json`（引擎寻路/房间地址：`address` + `collision`）；
3. 换图后角色出生/会议坐标是否还可走。

工具：`provenance/tools/install_scene.py`（一条命令做完三件，含体检与备份）

```bash
# 只看会怎么改（同时把待填名的 gid 表写到 tools/gid_map_tilemap2.json）
python tools/install_scene.py --tmx provenance/frontend/static/assets/village/tilemap/tilemap2.tmx \
    --maze provenance/case01/injector/scenario/maze.json --dry-run

# 真装（房间名填好之后）
python tools/install_scene.py --tmx ...tilemap2.tmx --gid-map tools/gid_map_tilemap2.json \
    --maze provenance/case01/injector/scenario/maze.json \
    --maze provenance/case00/scenario/maze.json --install
```

要点与坑（都实测过）：

- **外部 tileset 引用要清掉**：`tilemap2.tmx` 里挂着 `trading_32.tsx` / `trading_grid.tsx`
  两个外部 tileset，一格都没用到；它们没有 `name`/`image`，Phaser 载入会报错。工具会剔除。
- **Tiled 导出会把本机绝对路径写进 JSON**（`D:/zzr/...`），工具改写成相对写法。
- **collision 口径**：`maze.json` 的 `collision: true` 来自 Tiled 的 `Collisions` 图层（非 0 即阻挡）；
  `tiles` 只保留"有地址或有 collision"的格子（旧图 360 格就是这个口径）。
- **地址口径**：`Sector Blocks` → `Arena Blocks` → `Object Interaction Blocks`，
  名字由 `tools/gid_map_*.json` 给；没给名字的用 `SECTOR_x` 占位并打印催填（不许静默）。
- **前端只有一份地图，case00/case01 共用**：换图后两份 `maze.json` 都要重生成，
  否则另一边的人会站在旧格子上。
- 换上的是用户新做的 **tilemap2**（室内交易厅）：27×24 格不变，
  最近一次安装 maze = 623 格（有地址 512 / 阻挡 178）。
- `tilemap.tmx` 仍是**旧**场景（还带 Exterior 层），没有被替换。
