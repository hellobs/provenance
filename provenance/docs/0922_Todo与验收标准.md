## 一、判定路线（受控实验的分支分流）

**1. 分支判定的实现与失效策略** —— 归属：引擎侧实现，口径待研究侧拍板
- 现状：判定器本就是一次调用（`LLMBranchJudge(llm, prompt).judge(T0 回答)`），`llm` 可注入；失败策略与后端选择尚未定义。
- 任务：判定后端做成 `api | local | rules` 三档；降级链 API → 本地模型 → 规则表；每次把**实际用了哪一档**写进记录；
  并把"分支 + 理由 + 立场 + 一致性"合并到**同一次调用**（避免变成两次 API）。
- 验收：单局对 API 的调用次数 = 1；降级跑在记录与质检标记里可见；判定留痕含模型名、提示词版本、原始响应。
- 待定：用哪家 API / 哪个模型；API 失效算失败还是降级；是否一次调用含一致性。

## 二、平台对接

**2. 面向治理平台的对接准备** —— 归属：引擎侧（我方只读面）
- 现状：5010 已是唯一入口，CORS 已生效；缺深链、无 postMessage、无交接包、绑定地址固定 127.0.0.1、失败态是白页。
- 任务：补齐上述五项；写一页《给平台侧：嵌入与数据接入》（iframe 片段、数据调用、字段语义、协议、失败态、冒烟清单）；
  契约里写清"哪些嵌入面属于哪台引擎"（受控实验面有结果面板，沙盒面有治理面板与干预时间轴）。
- 验收：平台侧按这一页在 5 分钟内能嵌出场景并取到数据；跨机可访问（绑定地址可配置）。
- 后端分工：我方只提供**只读**数据面与嵌入面；建单、专家池、冲突加人、5 人多数、Approve/Edit/Reject 归**平台侧**。

## 三、稳定性与可观测性

**3. 大场景运行不易中断、错误可处理** —— 归属：引擎侧
- 现状：记录已改原子写；但仍无看门狗、无统一断点续跑、无保留策略、无运行指标；`print` 181 处 vs `logger` 8 处。
- 任务：看门狗（被杀自动重起并留日志）；统一断点续跑入口；结果保留策略与归档命令；运行指标（耗时/token/失败率）。
- 验收：杀掉进程 30 秒内自动恢复且有日志；中断后 `run.json` 完好无半截；一条命令给出保留/归档结果。

**4.（新增）可观测性** —— 归属：引擎侧
- 现状：几乎没有结构化日志；时间戳是本地裸时间（`datetime.now()` 5 处、`utcnow` 0 处）。
- 任务：统一 logger（级别 + 落盘）；时间统一 UTC 并在记录里留时区。
- 验收：跑一局，日志文件里有完整时间线；跨机器两局时间可比较。

**5.（新增）接口分页与过滤** —— 归属：引擎侧
- 现状：`/api/runs` 全量返回，记录多了嵌入面先崩。
- 任务：`limit / offset / quality / source` 参数。
- 验收：500 条记录下嵌入面打开仍流畅。

## 四、资料与复现

**6. 接入研究侧资料并注入 agent 上下文** —— 归属：引擎侧实现，资料由研究侧提供
- 任务：按通道分层——资料→检索库、人设→角色配置、事件→时间线、判定口径→scenario；**实验元信息不进 AI 可见处**；
  先出准入清单 + 校验脚本（禁用词、格式、来源标注、内容哈希）。
- 验收：材料入库后 AI 可见文本不含任何实验元信息（有测试拦）；记录里能查到资料版本哈希。

**7. 一次受控实验可复现** —— 归属：引擎侧
- 现状：manifest 已落地（git commit、引擎、判定后端与模型、温度、scenario/提示词/资料哈希）。
- 任务：把 `engine_id` 统一记引擎注册名并另加 `driver` 字段；preset 模式下补 `judge_used: false`；
  口径/提示词/资料变更写变更日志。
- 验收：拿到任意一局可复算它用的版本；口径变更后历史记录的可比性有明确说明。

**8.（新增）重复实验与统计出口** —— 归属：引擎侧（研究侧定义指标）
- 任务：同条件跑 N 局的批量入口；跨局统计（分支分布、判定稳定性、问题条数）。
- 验收：一条命令输出 N 局统计。

**9.（新增）判定与反思的质量验证** —— 归属：研究侧标注，引擎侧做工具
- 任务：20–30 条人工金标；测判定准确率与同输入一致性；反思/问题拆分同样抽样评估。
- 验收：给出准确率与一致性数字。
