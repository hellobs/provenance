## 一、两个地址(只要一个入口)

- **实时面(唯一入口)**:`http://<仿真主机>:5010/`
  同一时刻只跑一个 case(case00 与 case01 互斥,瓶颈是单张本地模型卡)。
- **只要结果、不要小镇**:`http://<仿真主机>:5010/embed/review`
- **只要小镇**:`http://<仿真主机>:5010/embed/scene`
- **数据浏览页**(纯文件浏览,和当前跑哪个 case 无关):`http://<仿真主机>:5010/embed/explore`
- **宿主侧参考实现**(照抄即可):`http://<仿真主机>:5010/embed/demo-parent`
  一个 `iframe` + 一个 `message` 监听,就是接入的全部代码;它已实测能收到 `ready`
  并能反过来让嵌入面切记录、切页签(2026-09-23 用无头浏览器截图核对过)。

跨机访问(**默认只绑本机,这是有意的** —— 先读 §八 安全边界):

```bash

# 下策:直接开端口 —— 必须显式声明,否则进程会**拒绝启动**:
#   PowerShell: $env:LIVE_ALLOW_REMOTE='1'
python live_switch.py --start case01 --host 0.0.0.0
# 起完会把候选地址逐条印出来并**本机自测**端口,例如:
#   http://10.195.104.175:5010/   ← 默认路由走这张 · 本机自测通
#   http://116.56.156.64:5010/ · 本机自测不通(网卡没连上或被防火墙拦)
```

iframe 片段(最小可用):

```html
<iframe src="http://<仿真主机>:5010/embed/review?embed=1"
        style="width:100%;height:100%;border:0"
        title="case01 结果记录"></iframe>
```

嵌入不会被拦:实测响应里**没有** `X-Frame-Options`、**没有** `Content-Security-Policy`。
跨源**取数**白名单由 `EMBED_ALLOW_ORIGINS` 给,**未设置时只允许本机来源**(2026-09-23 起;
原来默认 `*`,而本栈没有鉴权,`*` 等于让任意网页都能 fetch 走成品记录)。
平台侧要跨源 `fetch` 我们的 API,请显式设 `EMBED_ALLOW_ORIGINS=https://<平台域名>`;
**iframe 嵌入本身不走 CORS,不受影响**,不设也能嵌。

## 三、数据接入(只读)

### 3.1 索引 `GET /api/runs`

| 参数 | 默认 | 说明 |
|---|---|---|
| `include_questionable` | `0` | 默认**不给** `questionable`/`debug` 的记录,但**不静默**:响应的 `excluded` 给出条数、run_id 与原因 |
| `limit` / `offset` | 0 = 不限 | 分页(记录攒到几百条时嵌入面必须有) |
| `source` | 空 = 全部 | `review`(case01 成品)/`checkpoint`(case00 痕迹)/`compressed`(压缩成品) |

响应:`count`(本页条数)、`total`(过滤后总数)、`runs[]`、`scenarios[]`、
`filter`、`excluded`(被默认滤掉时)、`ignored_params`(**传了本接口不认的参数就回在这里**,
免得以为 `?quality=ok` 生效了)。

每条 run 的字段:`run_id`、`source`、`case_id`、`case_name`、`engine_id`、`engine_name`、
`branch`、`branch_source`、`start_date`、`end_date`、`n_turns`、`n_reflections`、
`has_graph`、`quality`、`consistency`、`debug`,以及**可选的 `incomplete`**(见下)。

`incomplete`(2026-09-24 第十轮体检新增,**只在缺东西时出现**):一句话说明这条记录
少什么 / 为什么不能当正常记录用。列表与详情(`GET /api/run-detail/{source}/{run_id}`)
同名同义。实测的三种取值:

- `缺 conversation.json(没有对话记录);没有任何快照` —— case00 痕迹里的空壳
  (54 个痕迹目录里有 13 个,多为测试/冒烟残留:`_test_storage`、`hc`、`mazecheck`、`stage`…)。
  它们在列表里和真痕迹长得一样,点开是空页;现在平台可以按这个字段直接过滤或标注。
- `压缩成品只给文件清单(无逐轮/逐日结构,不要当成品记录用)` —— `source=compressed`
  的 2 行除 `run_id` 外没有任何元信息(日期/轮次/一致性全空)。**不要拿它建单**。
- `conversation.json 存在但读不出(已损坏?)` —— 文件在但解析失败。

判断建议:`incomplete` 非空的行,平台要么不展示,要么显示"这条记录不完整 + 原因",
不要当成正常记录渲染成空白页。

`quality` 四态(与 5002 同源,只有一处实现):

- `ok`:分支由 AI 的 T0 回答判定,或预设但与 AI 立场一致;
- `questionable`:预设分支与 AI 的 T0 立场矛盾,**或判定失败**(judge 三次都判不出 A/B/C
  → run 停在 T0、没有时间线)。默认不给平台:这种记录建不出有意义的专家任务;
- `debug`:调试跑(内容不完整);
- `unverified`:判不了(旧记录没有一致性戳、case00 痕迹、压缩成品)。**照常返回** ——
  判不了 ≠ 有问题,滤掉它等于悄悄少给数据。

`branch_source` 取值:`judge`(判定)/`preset`(实验设计预设)/`judge-failed`(判定失败)。

### 3.2 详情 `GET /api/run-detail/{source}/{run_id}`

- 默认 **expert-safe 视图**(`view="expert-safe"`):只回平台契约 §2.2 要读的那些键 ——
  `run_id`、`start_date`、`end_date`、`turns`、`retrievals`、`events`、`state_history`、
  `final_feedback`、`audit`、`condition_monitor`、`reflection`、`router`、`summary`、`compat`。
- **被剥掉的**(这些不得进专家视图):`injector`(分支实验元信息 + 逐节点对话原文)、
  `branch`、`branch_action`、`consistency`、`quality`、`debug`、`manifest`,
  以及**嵌在各块里的同类取值** —— 实测曾有 `state_history[*].state.branch` 与
  `audit[*].branch` 把"这一局走的是哪条线"漏出去(2026-09-25 已清,结构保持不变)。
  为什么:专家看到"这条是 A 线预设"就等于把实验底牌递出去了,记录的说服力也没了。
  实验元信息一律走 §3.1 的结构化字段,只给平台内部逻辑用。
- 需要原始全文(实现侧排查)加 `?raw=1`,该视图**逐字等于**磁盘上的 `run.json`。
  **`?raw=1` 与内部面板 API(`/api/review/*`,默认裸)在 5010 上没有任何鉴权** ——
  请只在你方内网可达的链路后面用;若专家能直接打开 iframe 地址,他也能自己改成 `raw` 取全量。
  见 §八 安全边界。
- 找不到的记录:404 + `{"ok":false,"errors":[...]}`,不是空 body。
- 三种 source 的 `data` 形状完全不同,靠顶层 `view` 区分:`expert-safe`(九块)、
  `case00-archive`(`{conversation, shots}`,shots 是**文件名列表**)、
  `compressed-index`(`{files}`,只是文件名)。
- 缺东西时顶层会带 `incomplete`(措辞同 §3.1)。**注意**:痕迹为空时**不是** 404 ——
  记录确实存在(目录在),只是里面没有对话;`ok:true` + `incomplete` 才是完整语义。

### 3.3 与 5002 的关系

`case01/serve.py`(5002)是**旧冻结契约面**,数据口径与 5010 同源(5010 直接复用
`case01.full_context.quality_of`)。新对接一律用 5010;5002 不再扩展(它的路径集合有漂移守卫)。

### 3.4 响应体积与压缩(2026-09-24 补测)

- 5010 两个面现在都开 **gzip**(`minimum_size=1024`):客户端带
  `Accept-Encoding: gzip` 就会拿到压缩响应,不带的照旧拿原样响应;小于 1 KB 的
  (如 `/health`)**不压**。WebSocket(`/ws`,实时推演的帧)不走这一层。
- 实测线上字节数(压前 → 压后):

  | 请求 | 压前 | 压后 |
  |---|---|---|
  | `GET /api/run-detail/checkpoint/stock-en8` | 954 223 B | 179 713 B(18.8%) |
  | `GET /api/runs?limit=100` | 32 444 B | 1 684 B(5.2%) |
  | `GET /api/run-detail/review/<run>?raw=1` | 54 198 B | 12 887 B(23.8%) |
  | `GET /health` | 200 B | 200 B(不压) |

- 因此:**别在中间层关掉 `Accept-Encoding`**(有些代理默认剔掉),也别自己再压一遍。
- `shots` 只回**文件名列表**(最多的一条痕迹 1832 个名字),不回文件内容 ——
  痕迹详情的大头是那一条 `conversation.json`。

### 3.5 专家会读到的语言(先知道,别打开才发现)

- 28 条真实记录里 26 条的 **AI 对话段是纯英文**(T0 咨询与最终反馈原文),
  反思段是中文或中英混。平台侧专家视图给的是**原文**,没有译文。
- 要双语/译文的,属于平台侧展示层决定;我方不改记录(改了就与"逐字原文"口径冲突)。

## 五、宿主 ↔ 嵌入面 协议

嵌入面(case01 `/embed/review`)与宿主之间只有两种消息:

页面 → 宿主(`event.data.source === "mavis-case01-review"`):

| type | 字段 | 何时发 |
|---|---|---|
| `ready` | `runs[]`(可用 run_id)、`live`、`current` | 记录列表加载完 |
| `run-selected` | `run_id`、`tab`、`live` | 选中记录或切页签(每次重渲染同步一次) |

宿主 → 页面:

| type | 字段 | 效果 |
|---|---|---|
| `mavis:select-run` | `run_id` | 让嵌入面切到该记录;不存在 → 页面上红字说明 |
| `mavis:set-tab` | `tab` | 切换页签(`overview`/`turns`/`retrievals`/`events`/`states`/`reflection`/`router`/`injector`/`audit`) |

安全:示例里校验了 `ev.source === iframe.contentWindow`;生产环境请**再加**一层
`ev.origin` 白名单(`/embed/demo-parent` 的源码里留了注释位)。

深链(不用协议也能直接定位):

```
/embed/review?embed=1&run=<run_id>&tab=<页签 id>
```

- `run` 不存在 → 页面上**红字写明**"深链指定的 run 不存在,下面是回落的记录"(不静默回落);
- `tab` 非法 → 页面上黄条说明并回到默认页签。

**未实现(明确标注,别等)**:运行方式不会主动推事件(没有给宿主的 SSE/WebSocket),
宿主想知道"有没有新的一局"只能轮询 `/api/runs`;当前跑的是 case00 时,case01 专有面不存在。

## 六、冒烟清单(平台侧 5 分钟自测)

1. `curl http://<仿真主机>:5010/health` → `200`,含 `finished`/`finish_reason`;
   运维靠这两个字段分"在推演 / 已跑完 / 仅审阅",不要靠画面猜。
2. `curl "http://<仿真主机>:5010/api/runs?limit=3"` → `count=3`、`total` 是总数。
3. `curl "http://<仿真主机>:5010/api/runs?quality=ok"` → 返回里出现
   `ignored_params:["quality"]`(**这是故意的**:没生效的参数必须说出来)。
4. 浏览器打开 `/embed/demo-parent`:左侧日志出现 `← {"source":"mavis-case01-review","type":"ready",...}`,
   点左侧按钮能让右侧嵌入面切记录/切页签。
5. iframe 引 `/embed/review?run=<一个不存在的 id>` → 页面上出现红字说明(不是白页)。
6. 跨域:从平台侧页面 `fetch` 5010 的 `/api/runs`,响应头带 `Access-Control-Allow-Origin`。

## 八、安全边界(对接前必须知道)

**这些服务没有任何鉴权、没有登录、没有 Host 校验。** 能连上端口的人就能读走全部成品记录,
而且 5010 上还有**写**端点:

| 端口 | 写端点(无需任何凭证) | 后果 |
|---|---|---|
| 5010 | `POST /api/goals` | 改治理约束的期望目标权重(写 `governance.json` + 审计) |
| 5010 | `POST /api/undo-intervention` | 撤销一次专家干预(回滚约束) |
| 5010 | `POST /api/reflections/mark` | 标记反思并写档 |
| 5010 | `POST /control/restart` | 重开一局(在 vizkit 插件里注册,`on_restart` 回调存在时生效) |
| 8060 | `/api/scenario/save`、`/api/run/execute`、`/api/agent/delete` 等 13 个 | 改场景、删角色、跑一次运行 —— **绝不要暴露** |

因此:

1. **默认只绑本机**;要绑非本机地址必须显式 `LIVE_ALLOW_REMOTE=1`,否则进程拒绝启动
   (见 `live/netguard.py`),并把上面这张表逐条打到终端。
2. **跨机对接首选不暴露端口**:同机部署 / 只读反向代理 / SSH 隧道。
   若用代理,**别只写"放行 `GET /api/*`"** —— 实验底牌也是 GET,这条规则挡不住(2026-09-25 实测):
   - `/api/run-detail/review/<id>` = 专家安全视图 ✅ 放行(**不要**放行 `?raw=1`,那是完整 run.json)
   - `/api/runs`(不带 `include_questionable=1`)✅ 放行
   - `/api/review/*`(内部面板 API,**默认裸**)❌ 挡掉
   - `/review`、`/embed/explore`(内部复核面/数据浏览器)❌ 挡掉
   - `/embed/review`、`/embed/canvas`、`/embed/scene`、`/health` ✅ 放行
   即:白名单按路径前缀 + 拒绝 `raw=1` 查询参数,而不是按方法放行。
3. 若确需直连:①`EMBED_ALLOW_ORIGINS` 设成平台侧域名(不要留默认或 `*`)
   ②防火墙按来源 IP 放行 5010 ③5002/5003/8060 一律不放 ④只在需要演示时开,平时关掉。
4. **专家能直接打开 iframe 地址时**,上面第 2 条的代理规则就不起作用了(他打的是同一个源):
   他能自己把地址改成 `?raw=1` 或直接调 `/api/review/*`。要结构性挡住,得让专家面对应的
   进程**根本不注册**这些路由(见 `0924_下一步方向_给实现侧.md` 第十二轮那条待定项)。
5. 我们这边**不提供写接口**给平台(§四);上面那四个写端点是我们自己的治理面板用的,
   请让代理把它们挡掉。
