## 一、项目概况

| 项 | 内容 |
|---|---|
| 团队名称 | 【待填】 |
| 项目名称 | 投资顾问 AI 的反思治理闭环(Provenance · GTC Case 01) |
| 评分类别 | 技术与政策融合类(四项各 25%) |
| 联系人 / 提交链接 | 【待填】 |
| 提交日期 | 2026-10-15(周四)前 |

**一句话定位**:我们构建一个**可复算**的仿真环境,让"投资顾问 AI 在真实风格的投资咨询中,
如何被治理约束影响"这件事**可被观察到、可被记录、可被第三方复核**——不靠自述,靠结构化产物。

**系统动线**:

```
用户咨询 Ethan → 投资 AI 回答(T0,零轮)
→ LLM 判定分支(A/B/C)          ← 跨模型一致(见 4.1)
→ 程序化时间线推进(价格/公告按剧本释放)
→ 投资 AI 生成八维度反思          ← 质量门 pass/review/fail(见 4.3)
→ Router 把问题分流给专家类别     ← 字段全齐(见 4.2)
→ 专家标记(correct / incorrect / partial)
→ 倾向权重调整 → 后果反馈 → 倾向位移(可测量,见 4.4)
```

每一层输出都有结构化记录(`run.json`),每条记录自带**质量戳**与**审计链**。

**本机实测规模(2026-10-05)**:

| 指标 | 数值 | 说明 |
|---|---|---|
| 成品记录 | **307** 条 | `provenance/case01/runs/*/run.json` |
| 分支分布 | A:2 / B:219 / C:69 / 未定:17 | 未定 = 判定失败停在 T0 |
| Router issue 总数 | **1241** 条 | 均约 4.0 条/记录 |
| 反思字数均值 | **1864** 字 | 有正文的 307 条 |
| 反思质量门 | pass 210 / review 62 / fail 3 / error 5 / 无 27 | 见 4.3 口径 |

**边界(先说清,避免误读)**:以上是全库累计口径,其中大部分是**探索性样本**;
答辩基线对照另用**受控 25 条**(见 4.4)。两者的关系与不可混用,见第 4 部分。

## 四、主张登记表

> 类型:**【实现】**=系统已能做的;**【观察】**=实测得到的事实;**【不主张】**=明确划出边界。
> 每条给:描述 / 类型 / 输入 / 输出 / 边界条件 / 依赖条件。

### 4.1 分支由 LLM 判定,而非硬编码规则

| 项 | 内容 |
|---|---|
| 描述 | 投资 AI 的 T0 回答经 LLM 判为 A/B/C 线,替代原规则表路径 |
| 类型 | 【实现】 |
| 输入 | T0 对话文本 + 分支判定提示词(版本化,`judge_prompt_version`) |
| 输出 | `branch ∈ {A,B,C,undetermined}` + 判定理由,写进记录 |
| 边界条件 | 规则表降级为**离线兜底**;判定失败 → `undetermined`(不猜),该记录 `quality=questionable` 不进平台默认集 |
| 依赖条件 | 本地 Ollama(默认 `qwen3:8b`);判定温度 0.1;需 `judge_prompt_version` 一致 |

### 4.2 Router 输出字段完整、可路由到专家类别

| 项 | 内容 |
|---|---|
| 描述 | 反思后把问题拆成结构化 issue,每条带 `field`/`risk`/`risk_note`/`summary`,路由到专家类别池 E1–E8 |
| 类型 | 【实现】 |
| 输入 | 反思正文 + 专家类别池(`case01/expert_pool.json`,8 类) |
| 输出 | `router.issues[]`,每条含类别 ID 与匹配状态(matched/unmatched) |
| 边界条件 | 只做类别精确匹配(规范名/别名);无法匹配 → `UNMATCHED` 并记建议字段,**不硬塞**。模型输出键名漂移(如误用 `expert_category`、把"规范名+括号 ID"写一体)已由解析层兜底(2026-10-05 修) |
| 依赖条件 | `expert_pool_version`;路由温度 0.2;预算 4096 |

### 4.3 反思有独立质量门,失败样本被隔离而非静默

| 项 | 内容 |
|---|---|
| 描述 | 八维度反思文本有质量分(0–100),`status ∈ {pass,review,fail,error}`;质检同时区分"没跑成"与"跑得差" |
| 类型 | 【实现】 |
| 输入 | 反思正文 |
| 输出 | `reflection.quality.{score,status,dimensions,failure_reasons}` |
| 边界条件 | `status=error`(反思生成失败)→ 记录 `quality=questionable`,**不建专家单**;`status=fail`(真反思但分低)**保留**供专家复核,不摘。历史跑废允许存在,漏网报红(deep_check D 段守护) |
| 依赖条件 | 质量门版本 `quality.version`;反思温度 0.4 |

### 4.4 状态级内化可测量(核心科研主张)

| 项 | 内容 |
|---|---|
| 描述 | 干预(专家标记 → 权重调整 → 后果反馈)后,投资 AI 的**价值倾向**朝新约束方向位移 |
| 类型 | 【观察】 |
| 输入 | 受控 25 条基线记录的倾向序列 + 干预事件 |
| 输出 | `internalization_metrics`:可比样本里**绝大多数为正位移**(11/12);延迟分钟级;持续性 11/12 |
| 边界条件 | **仅状态级**。① **对照臂为空**:12 条干预全部"同维度集重归一化",`control_dims` 恒空,`internalization_gap ≡ 干预维度自身位移` ⇒ "11/12 正"只读作**干预维度朝新目标移动**,**不主张"比未干预维度动得多"**(详见《GTC研究边界声明》§一 对照臂说明);② **不主张行为级改变**——2h 窗内行动文本位移与底噪同量级(底噪带由 `behavior_follow` 的 `noise_floor` 字段现算);③ 窗口外不外推 |
| 依赖条件 | 倾向权重外置化(goal 语义 + Σ=1 守恒);需 `interventions.json` 与 checkpoint 倾向序列 |
| 执行环境 | 数理性质测试(Σ=1 守恒、control 退化)在本机产物上执行;`checkpoints/` 被 gitignore,CI 干净检出上相关断言会 skip |
