# 组合—运行—展示链路与统一数据界面的实施规格

面向工程实现的技术规格。内容覆盖三个目标：组合命名简洁化、运行后自动跳转前端并让引擎决定可视化组件、以及带导航菜单的完整数据界面。每个改动点给出对象文件与行号、具体做法、边界约束与验收判据。

本文所有“现状”均基于 **2026-09-20** 对仓库 `D:\zzr\mavis\config_tool`、`D:\zzr\provenance\provenance`、`packages/mavis-vizkit` 的核验。

---

## 1 现状基线

三个仓库当前的职责与断点在核验中已确认：

- **配置工具** `mavis/config_tool`：`/run` 页管理组合注册表，`/api/run/execute` 执行运行并**异步**切换 5010 实时面（`app.py:997`、`_launch_live` `app.py:96-122`）。运行完成后不跳转，只把摘要渲染在 `#result`，并把“5010 已切到 … :5010/”藏在 `notice` 文本里（`run.html:134/144`）。
- **引擎** `case_engine`：只有两个引擎 `experiment-eval`、`sandbox-value`，注册表 `ENGINES` 仅含描述元信息（`engines.py:20-33`），`EngineStrategy` 只有 `supports/describe/run`（`strategy.py:18-31`），**没有任何“引擎→可视化组件”的声明**，`run()` 尚未接可视化管线。
- **实时面渲染**：面板显隐由服务端模板变量**按 case 写死**——case00 `governance=True`（`live/routes.py:108`），case01 `governance=False`（vizkit `live.py:317`）+ `extra_panels`。`governance` 是布尔不是集合，随 case 变，不随引擎变。
- **数据存储三处分离**：case00 痕迹（`results/checkpoints/`，`state.py:221` 定根）、case01 成品（`case01/runs/<id>/run.json`，历史契约 `review_app.py:145` 的 `/api/review/runs`）、压缩成品（`results/compressed/`，无 API）。
- **前端导航**：无 header/nav。单页堆叠 + embed 子路径。`static/vendor` 已带 Bootstrap3+jquery+phaser 本地资源（`base.html:7-20`），具备搭导航的基础。

结论：三块都是“数据与渲染分离、缺统一驱动层”，而非缺数据本身。改造的核心是补齐三条驱动链——命名来源、引擎组件声明、历史数据契约。

## 2 目标一：组合命名简洁化

### 2.1 现状断点

组合默认名回退为 `"{case_id} × {engine_id}"`（`compositions.py:105`），显示为 `case00_village × sandbox-value` 这类带前缀与引擎 id 的长串。引擎展示名双份维护：config_tool 的 `SUPPORTED_ENGINES`（`scenario_builder.py:21`）与 `case_engine/engines.py` 的 `ENGINES` 文案不一致。case 展示名来自 `scenario.yaml` 的 `meta.name`，但组合记录里存的是目录 `case_id`。

### 2.2 改动

**命名来源（config_tool）**
- `compositions.py:105` 默认名改为可读组合：`f"{case_title} · {engine_name}"`，其中 `case_title` 取 `cases/<case_id>/scenario.yaml` 的 `meta.name`，`engine_name` 取 config_tool 侧 `SUPPORTED_ENGINES` 的展示名。仅在用户未填 `name` 时使用。
- 复用一个查询函数（在该文件内新增 `_comp_default_name`），保证新建与回显一致。

**去双份（配置侧为主）**
- 优先收敛到 `case_engine/engines.py:20-33` 的 `ENGINES` 为唯一事实源。config_tool 的 `SUPPORTED_ENGINES` 改为从 `case_engine.engines.ENGINES` 派生（name + primitives），不再自立副本。
- 若因 config_tool 依赖隔离不便 import，则在 `scenario_builder.py:21` 处加注释指引用同一份命名，并让两处 `name` 文案逐字一致。

### 2.3 验收

- `/run` 页新建组合时，空名字默认显示为 `场景名 · 引擎名`（如 `村庄治理 · 价值沙盒`），不再出现 `case_id × engine_id`。
- 已保存组合的手工 `name` 不受影响。
- 仅存在一份 engine 展示名定义；两处文案 diff 为空。

## 3 目标二：运行后自动跳转前端，引擎决定组件

### 3.1 自动跳转（改动最小）

现状断点：`/api/run/execute` 返回的 5010 地址埋在 `live.notice` 文本，前端不做跳转。

改动（config_tool）：
- `app.py:1027` 的返回体增加结构化字段 `live.redirect_url`，值即 `_launch_live` 已知的目标页 `http://localhost:5010/`（`app.py:120-121`），不再依赖解析 notice 文本。
- `run.html` 的 `runComp()`（`run.html:127`）在拿到 `res.live.switched && res.live.redirect_url` 后：
  1. 先轮询 `{redirect_url}health`（即 `http://localhost:5010/health`，该端点已存在并返回 case 标识）直到 200 或超时（约 20s），确保端口已就绪；
  2. 再 `window.location.href = redirect_url`。轮询失败则在 `#result` 展示“5010 未就绪，仍可手动打开”的一次性提示，不抛错。
- 跳转前保留当前 run 摘要写入本地 `sessionStorage`，前端新页可从同源 `sessionStorage` 读取组合名做页头展示（可选，见目标三）。

边界：只当 `switched=True` 才跳。`case_id` 无 `LIVE_ENTRY` 映射时（`_launch_live` 返回 `switched=False`）不跳，保持现有内联展示，语义不变。

### 3.2 引擎驱动组件声明

现状断点：面板由写死的 `governance` 布尔 + `extra_panels` 决定，与引擎无关；`EngineStrategy` 无组件挂点。

改动分四层：

**1. 策略层声明能力**（`case_engine/strategy.py`）
- 在 `EngineStrategy` 基类（`strategy.py:18-31`）新增 `panels(scenario) -> list[str]`，返回该引擎在给定场景下激活的组件 id 清单；基类默认返回空。`ExperimentEval`（`:33`）与 `SandboxValue`（`:101`）各自实现并给出第一版组件集。

**2. 注册表补元信息**（`case_engine/engines.py`）
- `ENGINES:20-33` 每条追加 `components: [...]`，作为引擎默认组件集合；`panels(scenario)` 的返回值与之保持一致并可被场景配置覆盖。

**3. 上下文来源改为按引擎解析**
- case00 `live/routes.py:108` 把写死的 `governance=True` 替换为：按活动引擎（`config.py:66` 的 `meta.engine`，或 `engines.build_for` `engines.py:94`）解析出的组件集合。组件集合与模板变量映射：集合含 `governance` 时置 `governance=True`，含 `timeline`/`reflection` 等按需扩展。
- case01 vizkit `live.py:317` 同法：`governance` 与 `extra_panels` 改由活动引擎的 `panels()` 决定。
- 模板 `index.html:207/229/257` 的 `{% if governance %}` 保留布尔兼容，但由服务端集合计算得到，不落引擎事实。

**4. 可选的运行期接口**
- 若前端需要在运行期刷新组件，新增只读端点返回“活动引擎 → 组件”映射（读 `ENGINES.components`），供前端按需查询。此端点不依赖引擎 `panels()` 执行，仅读元数据。

### 3.3 “反思回路 ABC”的语义定界

核验结果显示，系统当前没有三段式“反思回路 A/B/C 面板”。“AB”在此语境指**运行分支结果**：`branch.py:230-238` 将 no_buy/refuse 归到分支 B、conditional/anti_allin 归到分支 C，`config.py:221-244` 组装 rules，产出的 run 目录带 `-A/-B/-C` 后缀。反思的现有前端承载是 case00 独立页 `/embed/reflections`（`routes.py:855-965`，verdict=correct/incorrect/partial）与 case01 结果卡片的反射页签。

**建议**：把“反思回路 ABC”作为 `experiment-eval` 引擎的组件之一落地，含义取“本次 push 落入的分支 + 其反思结论”，前端渲染为对应 run 目录的后缀标记与反思面板。若期望的是真正三段推理回路（记忆→反思→决策的循环），需要先补充该引擎的推理图数据来源，成本显著更高。动工前用一次确认解决该语义。

## 4 目标三：统一数据界面与导航 Menu

### 4.1 现状断点

无导航。历史数据唯一的现成契约是 case01 `review_app.py:145` 的 `/api/review/runs`，返回 `runs[]` 摘要（`_brief()` `review_app.py:110-137`），但它只覆盖 case01 的 `run.json`。case00 的 `results/checkpoints/`（倾向序列 + interventions，端点 `/api/timeline` `routes.py:601` 只暴露“当前模拟”）与 `results/compressed/` 都没有历史列表接口。

### 4.2 统一历史数据契约

新增一个只读聚合端点（放 `case00` 实时面路由组，与配置工具共用数据契约），例如：

- `GET /api/runs` 返回 `{count, runs[]}`，每条字段对齐 `_brief()` 的结构：`run_id, case_id, engine_id, branch, start_date, end_date, n_turns, n_reflections, has_graph, source(checkpoint|review|compressed)`。
- 扫描范围 = `results/checkpoints/*` + `case01/runs/*` + `results/compressed/*`，各自归一化为同一摘要字段。三处目录都已有确定结构，归一化只做字段 XPath 映射，不迁移、不重写数据。
- 单条详情复用既有端点：case01 走 `/api/review/run/<id>`；case00 走 `/api/timeline` + `/api/reflections`；压缩成品暂只列目录不提供详情（可用 `/api/export-chart` 取图）。

### 4.3 前端导航骨架

- 在 `base.html` 挂一个 Bootstrap navbar（本地 `vendor/bootstrap.min.css`，无网络依赖），提供三个主视图入口：运行 / 当前场景(embed=scene) / 数据界面(embed=explore)。继承现有 `data-embed`（`base.html:12`，`main_script.html:93`）机制，约定 `embed=explore` 为新的数据视图。
- `explore` 视图复用 `index.html:149-167` 的 `extra-panel` 懒加载卡片范式：点击左侧 Menu 项 → 右侧 iframe 卡片懒加载对应 API 数据区。每个数据区一个卡片（概览 / 对话 / 检索 / 事件 / 状态 / 反思 / 问题分流 / 注入器 / 审计），数据来自统一 `/api/runs` 摘要 + 单条详情端点。
- 导航高亮用 `embed` 值驱动（设置当前项 `active` 类），保持与既有 embed 路由一致，不引入路由库。

### 4.4 与配置工具“一致”

数据契约统一取 `_brief()` 的字段命名，运维上配置工具与前端读同一套接口（都命中实时面的 `/api/runs` + `/api/review/run/<id>`）。config_tool 侧必要时在 `/run` 页底部加同源的历史列表（可选，非本规格必做），确保两处展示的字段一致即可。

## 5 里程碑与验收

改动的耦合度逐块递进，可按顺序落地，每块独立可验收、可回滚。

| 里程碑 | 内容 | 验收判据 |
|---|---|---|
| M1 | 组合默认命名简洁化 + 收敛 engine 双份注册表 | 空名组合显示 `场景名 · 引擎名`；engine 名仅一份定义 |
| M2 | 运行后自动跳转 5010 | 点运行 → 5010 就绪后自动打开前端；未就绪有兜底提示；无 `switched` 的组合仍内联展示 |
| M3 | 引擎组件声明 + 路由按引擎取 `panels()` | case00/case01 面板由活动引擎决定而非写死布尔；`EngineStrategy.panels` 有测试覆盖 |
| M4 | 统一 `/api/runs` 聚合 + 前端 navbar 数据视图 | Menu 三个视图可切换；数据界面列出三处历史 run；字段契约与 `_brief()` 一致 |

M1、M2 改动小、风险低，可先行；M3 是架构重构类，需在策略层补单测；M4 依赖 M2/M3 的 `embed` 与聚合端点就绪。

**每次改动后必须回归**现有约定：5010 单入口互斥（起 case00 停 case01）、case00 保留治理面板、case01 不显示治理面板与干预时间轴（本栈 `index.html` 的多情形渲染已由离线脚本 `tools/hc_template_render.py` 覆盖，改动后重跑确认 div 配平与显隐）。
