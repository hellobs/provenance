## 二、启动(二选一)

### 方案 0(一次起全部面:实时 + 契约 + 存档 + 布景)


- ⚠ **解释器在里层**:venv 是 `provenance\.venv-live`(仓根下**没有** `.venv-live`)——

- 默认 5010 是 **case01 只翻记录**(不占 GPU):要现场真跑加 `--full`;
- ⚠ **若 5010 上已有实例**(比如别人正用 `live_switch` 给 case00 讲的那一局),本工具会**先停掉它**
  再接上(`live_switch --stop all` 停**两个 case**),并把 `live_switch` 的现状表**打印出来** ——
  起面前看一眼那行输出,确认停掉的是你打算停的那个;
- 演示当天先 `--status` 自检,再按下面方案 A/B 讲。

## 五、故障回退(现场会踩,先背下来)

| 症状 | 原因 | 处置 |
|---|---|---|
| 打开记录详情**白屏** | 脚本把 `source` 猜成了 `checkpoint`/`compressed` | case01 记录一律用 `source=review`;`checkpoint`/`compressed` 只服务 case00,**对 case01 本就 404** |
| 调 API **404** | 用了 query string | `run-detail` 是**路径参数**:`/api/run-detail/{source}/{run_id}`,不是 `?id=` |
| `/api/runs` 里找不到某条 | 它是 `questionable`(被默认排除) | 加 `?include_questionable=1`;或看 `excluded`(5010 是 `excluded.runs` 列表) |
| 界面打不开 | 5010 没起来 / 被别的 case 占 | `cd D:\zzr\provenance\provenance` 后 `.venv-live\Scripts\python.exe live_switch.py --start case01 --review-only` 重启 |
| 想现场真跑但太慢 | GPU 串行,**单条 2–6 分钟**(不是几十秒) | 别现场跑;**用 `--review-only` 翻已有记录**。非要真跑:提前把模型预热,并**预算 2–6 分钟**(实测:qwen3:8b 全流程约 6 分钟;首轮 T0 更久) |
| 模型输出跑偏/串行 | Ollama 未驻留或换了模型 | `curl.exe -s http://127.0.0.1:11434/api/ps` 看驻留模型名 |

## 六、口径话说(评委可能追问)

| 会被问 | 标准答法 |
|---|---|
| "这个结果能复现吗?" | **分三档**:①产物级复算=能(命令在《复现说明》§二);②设定级复现=能,靠 `manifest`(git 提交/场景哈希/提示词版本/温度/种子);③**逐字重生成=现在不能承诺跨机**(同机同版本可大概率一致) |
| "AI 的行为真的被改变了吗?" | **不主张行为级改变**。我们主张**状态级内化**(价值倾向位移 11/12)与**反思层证据**;2 小时窗内行动文本位移与底噪同量级,如实说 |
| "这些记录该信哪几条?" | 按 `quality` 戳:默认只发 `ok` 的;`questionable` 被排除并**附理由**,可 `?include_questionable=1` 全量核对 |
| "审批/冲突升级在哪?" | 属**治理平台侧**职责,本系统只留接口与数据形状;**找不到不是缺陷,是分工** |
| "seed 设了吗?" | 是**可选开关**,演示轨与验证轨都设了(`20261004`);但设了也只保证**同机同版本大概率一致**,不越界承诺 |
| "issues 均值 4.7 的分母是什么?" | **154 ÷ 33**(`issues_total / n_scored`)。批次共 35 条,其中 **2 条 Router 未产出**(`skipped`)被剔除 —— 产物里就写着 `n_scored=33`、`n_excluded_not_scored=2`、`router_status_dist={ok:33, skipped:2}`,以及自述字段 `issues_mean_over="n_scored"`。**别报 35**,那是总数不是分母。⚠ 若被要求**现场复现**:今天重跑同一批次会得到 **130/27=4.8** —— 因为台账 35 条里有 **6 条 `run.json` 已不在盘上**(工具会自己打"与一手不一致:一手 35 条,本表 29 条"这行,不静默)。**引用时以入库产物为准,并主动说明这个缺口**,别让两边数字对不上 |
| "条件监控触发后做了什么?" | 如实说:**它是观测层,不是执行层**。311 条里 **70 条**带 `condition_monitor`(共 209 个条件;`keyword` 144 / `none` 63 / `price_below` 2),而 `fired=true` **只出现过 1 次**(`price_below 42`,收盘 40.7 那天);字段本身**没有动作/决策键** ⇒ **不主张"触发会驱动行为"**。复算:扫 `case01/runs/*/run.json` 的 `condition_monitor[].fired` 计数 |
| "现场能跑一条新的给我看吗?" | 能,但要**预算 2–6 分钟**(实测 qwen3:8b 全流程约 6 分钟);15 分钟脚本里没排它 —— 现场走查用 `--review-only` 翻已有记录。真要跑:先预热模型,再用 `--full` |

  - 自验命令(**PowerShell,本机已实测 22/22 通过**):
    ```powershell
    cd D:\zzr\demo-case01-20261015
    $ok=0; $bad=0
    Get-Content SHA256SUMS.txt | Where-Object { $_ -and ($_ -notmatch '^\s*#') } | ForEach-Object {
      $parts = $_ -split '\s+',2; $h = $parts[0]; $p = $parts[1].TrimStart('*')
      if (Test-Path $p) {
        if ((Get-FileHash $p -Algorithm SHA256).Hash.ToLower() -eq $h) { $ok++ }
        else { $bad++; Write-Output ("FAILED  " + $p) }
      } else { $bad++; Write-Output ("MISSING " + $p) }
    }
    Write-Output "OK=$ok FAILED/MISSING=$bad"   # 期望 OK=22
    ```
  - Git Bash 等价:`cd /d/zzr/demo-case01-20261015 && sha256sum -c SHA256SUMS.txt`;
  - 破坏性核对:改动任一文件后该项应 `FAILED`,可据此确认校验和不是空壳。
