# 给平台侧：什么是"运行方式"

> **状态**:现行
> **最后核对**:2026-09-24
> **说明**:面向平台侧的一页说明:运行方式是什么、你只需要认哪些接口、三个常见追问
> 本文不涉及内核实现细节,只讲"对平台可见的部分"。

## 一句话

**运行方式 = 一次运行的"运行策略"**：这一局怎么跑、按什么判、留什么证据。
一份研究写成**声明**（`scenario.yaml`：角色、时间线、要判什么、给谁什么信息），
运行方式就是执行这份声明的**可替换策略**。同一条可视化与审核流程，换运行方式就能跑另一类研究。

## 运行方式决定你界面上有什么（三点）

1. **一次运行激活哪些块**：运行方式注册表给出组件清单，例如受控实验是
   `scene / chat / reflection / overview / events / state / retrieval / router / injector / audit`，
   沙盒是 `scene / chat / governance / timeline / reflection`。
   平台做嵌入界面时，**按这个清单决定显示哪些面板**，不要写死。
2. **一次运行产出什么记录**：受控实验产出"一条分支线"的可审计记录
   （分支 A/B/C、一致性判定、反思原文、从反思切出来的待审问题）；
   沙盒产出的是长跑的状态/倾向快照。
3. **要不要人工介入**：沙盒有治理约束面板与干预时间轴；受控实验在运行中不干预；
   并且**沙盒也已不允许时间轴回滚**（后果属于角色的经历，不可倒带）。

## 现在有两种运行方式

- **`experiment-eval`（受控实验 / 评估）** —— 一次交互压成一条分支线：AI 在 T0 的回答决定走哪条线，
  系统再检查"AI 的立场与这条线是否自相矛盾"，然后由同一个模型生成反思、另一个模型把反思拆成
  若干**待审核问题**交给专家。**平台侧专家审核流程消费的就是这一路数据。**
- **`sandbox-value`（生成式价值权重沙盒）** —— 多个角色长期活动，价值权重随经历演化，
  专家可以在治理面板上调约束；它**不判分支**，也不产出"待审问题"。

## 你只需要认三个接口

- `GET /api/scenarios`：当前有哪些场景、各自推荐哪个运行方式；
- `GET /api/engine-components`：某个运行方式激活哪些组件（决定你的面板）；
- 每条运行记录里的 `engine` 与 `quality` 字段：
  `quality = ok / questionable / debug / unverified`；默认**不返回** questionable 与 debug，
  但响应里用 `excluded` 明确报出被排除了几条、分别是谁、为什么 —— 请不要把"少给了"当成"没有"。
- 专家审核要的正文（反思 + 待审问题）走**专家安全视图**：不含分支/预设/注入器等实验元信息；
  原始全文需显式 `?raw=1`（仅内部排查用，不要喂给专家页）。

## 三个常见追问

**"为什么沙盒没有分支判定？"**
分支判定属于"一次受控实验"的协议：一个 T0 触发、一个可判定的结论。
沙盒关心的是长期演化，没有"这一次买不买"这种单点结论，所以那套字段对它没有意义，
页面上也会按运行方式把不相关的配置/面板收起来。

**"我能不能自己加一种运行方式？"**
运行方式是注册表 + 策略接口（`supports / describe / panels / run`），加一台新运行方式不需要改可视化、
不需要改平台。新研究若不属于"受控实验"或"沙盒"这两类，我们会先把它定义成**第三种协议**
（而不是硬塞进现有两种），然后按协议加运行方式。

**"运行方式和你们那个 mavis 什么关系？"**
mavis 是多智能体仿真内核（角色怎么记忆、怎么行动、怎么反思）；
运行方式决定"这一局拿哪个场景、放什么事件、按什么判、留什么证据"。
两者是**上层策略与内核**的关系：运行方式调用内核，内核不知道运行方式存在。
平台侧不必关心这层，只需要认上面那三个接口。
