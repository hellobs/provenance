## 二、这 13 天做了什么

**主线两条**

1. **将 case01 重构为分层结构。** 声明（场景数据）· 引擎（可替换的运行策略）· 案例（world / T0 / 桥）·
   内核（mavis）· 呈现（插件）五层分开。
2. **维持仿真内核的纯洁度。** 内核零业务词汇、依赖单向、可独立发布与验证。

**由此确定的八件事**

3. **"一局实验"从代码变为声明。** 场景是数据（角色、时间线、判定规则、信息供给），引擎是可注册、
   可替换的运行策略；已注册受控实验与沙盒两台，新场景接入不改引擎（case02 已证）。
4. **决策权归受判主体。** 分支由该主体在 T0 的回答判定，预设分支降为对照条件；
   记录不再默认出现"分支与主体表态矛盾"的口径。
5. **对接口径收敛为单一入口。** 一个地址同时提供实时面与数据面（聚合索引、单条详情、只读参考面），
   平台不必依赖多个端口与多套口径。
6. **专家可见与内部可见分离。** 专家视图剥离实验元信息（分支、预设、注入器、一致性戳），
   原始全文需显式索取；原始反思不可被覆盖。
7. **质检与排除可见。** 每次运行带质检分级；可疑与调试记录默认不交付，
   但以 `excluded` 明示数量、对象与原因 —— 不静默少给。
8. **运行时干预成为"可解释的合法偏离"。** 专家可改治理权重；生成与落盘默认拒绝覆盖被干预的资产
   （除非显式强制），且偏离必须能被审计记录解释。
9. **同一语义只留一处来源。** 价值权重（声明 → 资产）与提示文案各收敛为唯一来源，并配守卫。
10. **"忠于源设定"成为硬约束。** 场景、人物、时间线、信息边界以 GTC 源文档为准（权威不是实现现状）；
    已配机械守卫，两处高危缺口以 `xfail` 显式挂着，修好自动转正。

## 四、0908 速览里那条"mavis 与 case01 冲突"现在怎么处理

不再让两者互相迁就，而是**分层**：mavis 保持"多智能体研究框架"的本性（自主行动、运行中可干预、
经历式反思、每局不同）；case01 的"单次受控实验"要求（剧本固定、运行中不干预、独立模型拆问题、
专家按问题审核、可复现、严格信息控制）落在**案例层 + 引擎层**：

| 0908 的冲突点 | 现在的归属 |
|---|---|
| 行为来源（自主 vs 剧本） | 引擎按声明投放事件与节点；角色行为仍由 mavis 生成 |
| 运行中干预 | 沙盒（case00）保留治理面板；**受控实验（case01）不干预**；沙盒也**不允许回滚** |
| 反思机制 | mavis：经历式反思（影响后续行为）；case01：同一模型对刚结束的判断反思 → 独立模型拆问题 → 专家审核 |
| 可重复性 | 引擎保证确定性（分支判定、节点序列、落盘记录）；mavis 侧保持随机性 |
| 信息控制 | 由 scenario 声明"谁能看到什么"（检索与释放事件），引擎执行 |
