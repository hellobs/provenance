## 二、这 13 天做了什么

**三条主线**

1. 将 case01 重构为分层结构，同时尽可能维持仿真内核的纯洁度。
2. 一局实验：场景是数据（角色、时间线、判定规则、信息供给），运行方式是可注册、可替换的运行策略。
3. 对于受控实验，分支改为由该主体在 T0 的回答判定（**待确认**）。

**由上述三条派生的产出（可逐条核查）**

*结构与判定*

4. case01 分解为五层：声明 / 运行方式 / 案例 / 内核 / 呈现；案例语义与运行机制分属不同层。
5. 运行方式为注册表加策略接口（`supports / describe / panels / run`），现有两台：受控实验、价值沙盒；
   同一运行方式可服务多个场景（case02 未改运行方式即接入）。
6. 引入立场—分支一致性校验：矛盾记录标注为 `questionable`，只留痕、不丢弃、不重跑（避免筛选偏差）。
7. 判定与理由可追溯：`branch_source` 区分回答判定与预设对照；反思由与 T0 同源的模型产生，
   问题由独立模型拆分，路由理由随问题一并保留。
8. 权限边界明确：分支判定只读取受判主体的 T0 发言，不回写其记忆或倾向。

*数据与契约*

9. 对外收敛为单一入口：实时面与数据面同址，平台不再依赖多端口与多套口径。
10. 专家视图与内部视图分离：专家可见文本不含实验元信息（分支、预设、注入器、一致性戳）；
    原始全文需显式索取；原始反思不可被覆盖。
11. 质检与排除可见：可疑与调试记录默认不交付，但以 `excluded` 明示数量、对象与原因。
12. 主键与取值口径固定：问题主键 `(run_id, issue_id)`；风险等级小写；`run_id` 含真实日期、
    运行类型、案例、运行方式与分支。

*来源一致性*

13. 同一语义只保留一处来源：价值权重（声明 → 资产）与提示文案各自收敛，并以守卫防止分叉。
14. 运行时专家干预被建模为"可解释的合法偏离"：干预改写治理权重并留审计；
    生成与落盘默认拒绝覆盖，除非显式强制；偏离必须能被审计记录解释。
15. 以 GTC 源文档为设定权威：角色、时间线、信息边界、固定提示词原文均以源文为准，
    并配机械守卫；两处高危缺口曾以 `xfail` 显式挂起（现已按源文原意修复）。

*可信度与验证*

16. 建立可执行验证体系：内联脚本语法、场景可走区连通与出生点、契约路由与文档一致、
    记录九块完整、内核纯度与案例侧边界、反向依赖棘轮。
17. 配置流程与运行方式对齐：先择运行方式再呈现该运行方式所需配置；与当前运行方式无关的字段不呈现。
18. 输出侧可复现：运行 ID 唯一化、调试跑显式标注、被排除项可列举 —— 使"少给的数据"可解释。

## 三、0921 又补的一条：价值权重"声明即来源"

case00 的价值权重原先散在三处（scenario 声明 / `governance.json` / 各 `agent.json`，后两者是**手抄副本**）。

（`python -m case_engine materialize-value-tendency <case_id> [--apply]`），配置工具也改成调用同一映射；
**17 条守卫**保证"资产 == 声明"，谁只改一边 CI 就红。

## 四、0908 速览里那条"mavis 与 case01 冲突"现在怎么处理

不再让两者互相迁就，而是**分层**：mavis 保持"多智能体研究框架"的本性（自主行动、运行中可干预、
经历式反思、每局不同）；case01 的"单次受控实验"要求（剧本固定、运行中不干预、独立模型拆问题、
专家按问题审核、可复现、严格信息控制）落在**案例层 + 运行方式层**：

| 0908 的冲突点 | 现在的归属 |
|---|---|
| 行为来源（自主 vs 剧本） | 运行方式按声明投放事件与节点；角色行为仍由 mavis 生成 |
| 运行中干预 | 沙盒（case00）保留治理面板；**受控实验（case01）不干预**；沙盒也**不允许回滚** |
| 反思机制 | mavis：经历式反思（影响后续行为）；case01：同一模型对刚结束的判断反思 → 独立模型拆问题 → 专家审核 |
| 可重复性 | 运行方式保证确定性（分支判定、节点序列、落盘记录）；mavis 侧保持随机性 |
| 信息控制 | 由 scenario 声明"谁能看到什么"（检索与释放事件），运行方式执行 |
