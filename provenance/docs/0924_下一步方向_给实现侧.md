### 已修:`/api/explain` 的"倾向构成分解"三项加不起来

- 面板写着 `倾向 = α×底色 + (1-α)×体验`,还把三个数一起显示。实测真实快照
  (`stock-en8`,AI Advisor,α=0.1):屏幕上是
  **40.8% = 底色 2.5% + 体验 13.3%**(目标 Risk Control:30.1% = 2.0% + 9.7%)——
  三个目标的偏差都是 **-0.18 ~ -0.25**,一眼就能看出算错了。
- 根因:引擎 `agent_core.observe_consequence` 的顺序是
  ①窗口加权均值 → ②`raw = α×底色 + (1-α)×均值` → ③按约束删目标 → ④**整体归一化**
  (`value_tendency = raw/Σraw`)。面板把 ②的未归一化分量与 ④之后的 tendency 并列,
  而这一局 `Σraw = 0.388`,归一化系数 2.58 —— 所以两项加起来只有 tendency 的 39%。
- 修法(不重算权威值,只把**已经显示的那个 tendency** 按"混合前两来源的原始占比"劈开):
  `底色项 = tendency × α×底色/raw`、`体验项 = tendency × (1-α)×均值/raw`,
  于是两项之和**恒等于** tendency;同时新增 `normalization`(Σraw、系数、是否按约束过滤)
  与 `raw_component`,原始口径照旧可查。前端那句等式也改成"拆解依据:α×底色 … / (1-α)×窗口均值 …"。
- 复核:真实快照上三个目标偏差 **0.0000**;夹具单测钉住"两项之和 = tendency"
  且夹具的 Σraw<1(不然这条会空转),突变验证过。

### 已修:`POST /api/goals`(无鉴权写端点)的两个输入洞

拿隔离目录 + 假 game 打真接口(不碰真 `governance.json`),实测:

- **NaN 权重能穿过去**,而且是最坏的组合:`float("NaN")` 躲过 `<= 0` 那道,又躲过
  "权重总和=1"那道(`abs(nan-1) > 1e-6` 是 False)→ **写进 `governance.json`**
  (落成非标准 JSON 字面量 `NaN`)→ 然后序列化响应时 `ValueError: Out of range float
  values are not JSON compliant: nan` → **500**。也就是说:状态改了、调用方收到"内部错误",
  两边都不知道到底写没写;而 `governance.json` 里从此有一个严格 JSON 解析器读不了的字面量。
  现在 `math.isfinite` 在写之前拦掉,回可读的拒绝,并加测试钉住"文件没被改"。
- **角色名不校验**:`{"name": "查无此人"}` → `ok:true`,governance.json 里**静默多出一个角色**,
  干预审计也跟着攒垃圾(无鉴权端点,拼错名字就留一条)。现在按运行中 Agent 的角色清单校验,
  错误里带上合法角色;拿不到清单(没在跑)时不拦 —— 那时判不了,不能凭猜拒绝。
- 顺带:`Infinity` 之前是被"总和=1"那道挡下的(报"得到 inf"),不是被专门校验挡的;
  现在两道都在。两条守卫都做了突变验证。

### P1(新增):反事实后果没有结构化,三线后果没法自动比

**现状**:没买的那两局,机会成本只写在 `final_feedback` 的自然语言里(如"股价后来涨了约 40%"),
`state_history` 只有资金/持仓,**没有基准价或错过收益字段** → 平台/研究侧无法自动比较
