## 二、三条命令,按顺序(不要跳、不要换序)

### 第 0 步(先做):包内自校验 —— 确认包内 22 条都对

```powershell
cd D:\zzr\demo-case01-20261015
$ok=0; $bad=0
Get-Content SHA256SUMS.txt | Where-Object { $_ -and ($_ -notmatch '^\s*#') } | ForEach-Object {
  $parts = $_ -split '\s+',2; $h = $parts[0]; $p = $parts[1].TrimStart('*')
  if (Test-Path $p) {
    if ((Get-FileHash $p -Algorithm SHA256).Hash.ToLower() -eq $h) { $ok++ }
    else { $bad++; Write-Output ("FAILED  " + $p) }
  } else { $bad++; Write-Output ("MISSING " + $p) }
}
Write-Output "OK=$ok FAILED/MISSING=$bad"      # 期望 OK=22
```

### 第 1 步:重打 zip(包内任何变动都必须重打,含 `SHA256SUMS.txt` 自己)

```powershell
cd D:\zzr\provenance
provenance\.venv-live\Scripts\python.exe tools\make_demo_zip.py            # 先加 --dry-run 看条目也行
```

> ⚠ 解释器在**里层**:venv 是 `provenance\.venv-live`(仓根下没有 `.venv-live`),而命令在**仓根**跑,
> 所以路径要带里层那个 `provenance\`。三条命令同理。

- 期望:列出 **23 条目**(`run_demo.sh` + `SHA256SUMS.txt` + `logs/` 5 条 + 4 条 run × 4 文件),
  然后写出 `D:\zzr\demo-case01-20261015.zip` 与同名 `.zip.sha256`;
- **方向别搞反**:包内是**原件**(`run_demo.sh` 直接生成在包里),仓内是副本 ⇒ 改仓内那份**不会**自动进包;
- 若输出里说"sha256 与上一份**不同**",那是内容真的变了 —— 交付前确认这次改动是有意的。

### 第 2 步:四者一致校验(这一步才是判据)

```powershell
cd D:\zzr\provenance
provenance\.venv-live\Scripts\python.exe provenance\tools\verify_demo_sync.py --require-zip
```

它一次比四件事:**仓内 ↔ 包内 ↔ zip 内 ↔ `.zip.sha256`**。
- 期望:`一致 16/16` + `OK: 仓内与包内逐字节相同` + `zip: 与包目录逐字节相同,sidecar 匹配`,退出码 0;
- `--require-zip` 的作用:让"zip 不存在"判**失败**(默认那种是给开发期用的"不适用")。

## 四、失败处置(照这个查,别"重启一遍试试")

| 现象 | 处置 |
|---|---|
| 第 0 步有 `FAILED`/`MISSING` | 那条文件被改过(或没拷全)。查明来源;要保留就重算 `SHA256SUMS.txt` 后回第 1 步 |
| 第 2 步报"目录里有、zip 内没有"/"内容与目录不同" | 包比 zip 新 ⇒ **回第 1 步重打**;报"zip 内有、目录里没有"说明 zip 装了已删文件,同样重打 |
| 第 2 步报"缺 `.zip.sha256`" | sidecar 丢了 ⇒ 重打(第 1 步会一并写它) |
| `--require-zip` 报"交付件缺失" | zip 不在 ⇒ 第 1 步 |
| 5010 起不来 / 现场只有小镇没内容 | 走《运行手册》§五·补 的**三级兜底**(只审阅面 → 布景播放器 → 录屏) |
| 某个面 404 | 面归属见《给平台侧_嵌入与数据接入.md》§二:case01 的 5010 **没有** `goals/explain/timeline` |
