# 平台对接契约 · 5010 唯一入口

> **状态**:现行
> **最后核对**:2026-09-21
> **说明**:**交给治理平台的唯一口径**:嵌入面 + 数据接口 + 质检口径 + 信息边界 + 运维(2026-09-21 起)
> 唯一对外口径:嵌入面 + 数据接口 + 信息边界 + 质检口径。5002(`case01/serve.py`)降为
> **引擎侧只读参考面**,不再作为平台对接目标(其数据/信息边界两节仍有效,见文末对照)。

## 一、一句话

平台只需要**一个地址**:

```
http://<host>:5010/
```

平台**只读**拉取 + iframe 嵌入,不写我们的库;评审流程(建单、专家池、冲突、归池)全在平台侧。
Provenance 不感知平台的存在(`live_switch.py` 起停,平台只负责引地址)。

## 二、嵌入面(iframe)

| 用途 | URL |
| --- | --- |
| 完整界面(小镇实时 + 右栏结果记录卡片) | `/` |
| 纯场景(只要 Phaser 画面) | `/embed/scene`(等价 `/?embed=scene`) |
| 结果面板(压缩版式,贴合 iframe) | `/embed/review`(等价 `?embed=1`) |
| 数据界面(历史 run 浏览) | `/embed/explore` |
| 治理面板(case00 专属) | `/embed/goals` |
| 干预时间轴(case00 专属) | `/embed/timeline` |

- **深链**:`?run=<run_id>&tab=<页签>`;页签 id:`overview / turns / retrievals / events / states / reflection / router / injector / audit`。
- 场景页的 WebSocket 按 `location.host` 拼,iframe 嵌到哪个端口都连得对。
- 本栈**不带 `X-Frame-Options` 与 CSP**(有测试钉死),所以 iframe 可直接嵌。

## 三、数据接口(平台只读)

| 接口 | 说明 |
| --- | --- |
| `GET /api/runs` | 聚合索引:case00 痕迹 + case01 成品 + 压缩成品,归一化摘要 |
| `GET /api/run-detail/{source}/{run_id}` | 单条详情;**默认专家安全视图**;`?raw=1` 才是原始全文(内部用) |
| `GET /api/review/runs` / `/api/review/run/{run_id}` / `/api/review/live` | case01 成品九块 / 实时状态(专家面板自己用) |
| `GET /health` | 存活 + 当前 case + `finished` / `finish_reason` / `can_restart` |
| `POST /api/undo-intervention` | 撤销一次专家干预(case00 治理面板用);**沙盒场景一律 403** —— 沙盒不允许时间轴回滚 |
| `POST /control/restart` | 重开一局(可选 body:`{"branch":"auto\|A\|B\|C"}`;仅运维/演示台用) |

### 3.1 质检口径(2026-09-21 新增,必须知道)

索引里每条 case01 成品带四个字段:

- `quality`:`ok` / `questionable` / `debug` / `unverified`
  - `questionable` = 预设分支与 Investment AI 的 T0 立场自相矛盾(例:AI 说"不能确认值得买"、当事人却满仓);
  - `debug` = 调试跑(如 `--nodes` 截断,内容不完整);
  - `unverified` = 旧记录没有一致性戳(**判不了 ≠ 有问题**,照常返回)。
- `consistency`:T0 立场与分支的一致性判定(`consistent` / `inconsistent` / `unknown` / `unverified`);
- `branch_source`:`preset`(运行参数指定) / `judge`(由 T0 回答判定)。
  **口径说明**:受控实验目前默认走 `judge`(即分支由受判主体在 T0 的回答判定),`preset` 保留为对照条件 —— **该默认口径仍待研究侧确认**,确认前请以字段实际取值理解数据;
- `debug`:调试跑说明(空串 = 正式跑)。

**默认行为**:`/api/runs` **不返回** `questionable` 与 `debug` —— 但不静默,
响应里带 `excluded{count, runs[], reason}`;要全量加 `?include_questionable=1`。
平台**不要**把"少给了"当成"没有这条记录":以 `excluded` 为准。

### 3.2 信息边界(硬约束)

- `GET /api/run-detail/{source}/{id}` **默认只回专家可看的白名单**
  (`run_id / 日期 / turns / retrievals / events / state_history / final_feedback /
  audit / condition_monitor / reflection / router`),并标 `view: "expert-safe"`;
- **不得进专家视图**:`injector`(Branch 实验元信息 + 逐节点 dialogue 原文)、
  `branch_action`、`consistency`、`debug`、`quality`、`branch` 标签 —— 与 0904doc 04 六.3 /
  《Governance平台对接说明》§2.3 一致;
- 专家的 `View Full Context` 走**自然语言全文**(5002 的 `/api/runs/{id}/full-context`,
  或 5010 `/embed/review` 的对应页签),该文本**不含任何实验元信息**(有守卫测试);
- **原始 Reflection 不得被平台/专家覆盖**(只读数据源)。
- 平台若确实需要原始全文(内部排查),显式用 `?raw=1` —— 请**不要**把 `raw` 视图喂给专家页。

### 3.3 主键与取值口径

- Router issue 的 `id` 是 **run 内序号**(`issue-1`…),跨 run 会重名 →
  平台建单/幂等主键必须用 **`(run_id, issue_id)`** 复合;
- `risk` 取值**小写** `low` / `medium` / `high`(平台比较时忽略大小写即可);
- `run_id` 命名:`<真实日期 YYMMDD>-<kind>-<case>-<engine>-<branch>[-HHMM]`,
  `kind ∈ {live, demo}`;judge 模式分支未知时名字里写 `auto`,**以记录里的 `branch` 为准**。

## 四、平台侧要实现的流程(状态机)

按 0904doc 04 七/八、05 四实现;**我们只提供问题与原文**:

```
Reflection + Router issues(/api/run-detail,专家安全视图)
   │  按 issue.field 匹配专家池,随机分配 2 位不同专家
   ▼
pending → assigned(2/2) ──结论互斥──> disputed
   │                                   │ 追加 3 位未参与专家(共 5)
   ▼                                   ▼
final(多数意见,少数保留) → 训练材料池(完整治理记录 + Audit Trail)
```

- 每个 issue 的专家意见 = Approve(反思核心成立)/ Edit(有遗漏或表述问题,只改该片段)/
  Reject(核心逻辑不成立);
- 一条 Reflection 拆出 N 个 issue 就建 N 条任务,共享同一 `run_id` 与同一条 Reflection;
- `router.ran == false` 或 issues 为空时,原始 Reflection 仍要进人工审核。

## 五、运行与运维

- 5010 由运维用 `live_switch.py --start case01|case00` 起停(case00/case01 **互斥**,瓶颈是单张本地 Ollama);
- 只想看结果不跑推演:`--review-only`(不占 Ollama);
- 我们的服务**会被外部清掉**(实测多次,无 Python 异常):
  正式演示前请重起,或按 `tools/run_live_watchdog.ps1` 的思路挂个看门狗;
- `/health` 的 `finished` / `finish_reason` 是"跑完没有"的唯一权威口径(不要靠画面猜)。

## 六、与 5002(旧冻结契约)的关系

- `case01/serve.py`(5002)仍是**引擎侧只读参考面**:三个端点 + `full-context` 自然语言全文;
  数据口径(小写 risk、复合主键、raw 反思不可覆盖)以它为准写就,本契约沿用它;
- 差异:5002 只有 case01 且**不含**嵌入面;5010 是唯一入口,同时提供嵌入与聚合数据;
- 若平台已经按 5002 接好,不必拆:两者返回的质检集合**同源**(5010 直接复用
  `case01.full_context.quality_of`),不会出现"两边数据不一致"。
