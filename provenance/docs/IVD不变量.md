# IVD 不变量（硬约束）

> 2026-09-21 立。用户拍板：**一定要遵从 IVD**。
> 配套可执行守卫：`case_engine/tests/test_ivd_invariants.py`（7 条）。
> 背景见本文末「为什么突然要立这个」——引擎/场景化重构之后，一等概念变成了
> Scenario / Engine / Run，决策权有从 agent 滑到"场景参数 + 引擎策略"的趋势。

## 一句话

**这套东西的主角是 agent：它自己判断 → 承担后果 → 反思 → 内化（IVD）。**
场景是它面对的**信息环境**，引擎是让这套流程**跑起来、跑得住、跑得可查**的机制。
两者都不能替它做判断。

## 五条硬约束

1. **决策由 agent 产生**。分支/结论来自 agent 自己的回答；场景**不得**写死"这次走哪条线"。
   —— 场景可以写判定词汇表（哪些说法算拒绝、哪些算条件化），但"这次是哪条"必须由回答决定。
2. **记忆与倾向归 agent 内核**（mavis）。上层只传参，不替它维护状态、不替它改倾向。
3. **场景只描述信息环境**：角色、时间线、信息条目、判定词汇、状态口径。
   它可以**规定怎么判**，不可以**规定判成什么**。
4. **引擎只做机制**：编排节点、落盘记录、校验一致性、提供展示面。
   **判断不行** —— 引擎策略类里不允许出现 `judge/decide/classify/route` 这类方法
   （守卫会枚举所有 `EngineStrategy` 子类检查）。
5. **"它为什么这么做"必须可追**：答案在 agent 的回答、记忆与反思里能查到。
   因此判定结果要带出处（`judge`/`reason`），反思正文只由 agent 自己产生。

## 守卫怎么检查（对应测试）

- `branch_args()` 只允许 `rules / default_branch / judge_prompt / fallback_map`；
  出现 `branch: "A"` 这类字段即失败（不变量 1/3）。
- `default_branch` 只在**判不出来**时生效：喂明确回答必须走规则给的线（不变量 1）。
- 同一场景喂两种回答 → 必须能落到两个不同分支（不变量 1：是回答在决定）。
- 枚举所有 `EngineStrategy` 子类，检查没有判断类方法（不变量 4）。
- `route()` 必须返回带出处的结果（不变量 5）。
- 反思入口的 prompt 必须可注入（引擎不写死案例口径；不变量 3/5）。

## 已知的历史疤痕（提醒：这几处正是漂移的后果）

- **case01 的 preset 分支**：分支由运行参数给，不看 AI 说了什么 ——
  实测出现过"AI 在 T0 说不能确认值得买，当事人却满仓买入"的自相矛盾记录。
  现在的默认已是 `judge`（由 T0 回答判定），preset 只作对照。
- **mavis 内核里的案例措辞**：`agent_core` / `prompt/scratch.py` 曾经各写一份"空闲待命"
  文案、其中一处还是中文，只能再补一段"中文→英文"兼容清洗兜底。
  2026-09-21 已收敛为单一来源 `mavisframework/idle_text.py`（默认通用英文、场景可覆盖），
  清洗表改由场景注入（`config["idle_text_map"]`），内核零案例词汇。
- **mavis 仓的 `config_tool` 反向依赖 provenance**：场景创建器/引擎运行器会探测
  `../provenance` 并复用 `case_engine` 的 schema。方向是反的，需要收口
  （要么工具搬去 provenance，要么显式环境变量指定、不再默认探测兄弟目录）。

## 为什么突然要立这个

引擎/场景化重构（2026-09-20 那批）把"可组合、可换引擎、场景即数据"做成了主线，
收益是通用性与复用；代价是叙事重心从"一个 agent 怎么想、怎么承担后果"移到了
"一份 YAML + 一个策略"。对 GTC 这套东西来说，**后者不是卖点**：
评审要看的是 agent 的判断如何在信息污染下失衡、后果如何落到具体的人身上、
反思如何把它内化。所以把这条线钉成不变量，谁改都不许越过。
