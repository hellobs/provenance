## 一、两层是什么(以及为什么会有两层)

```
D:\zzr\provenance\            ← 仓根:**工程与管理面**
├── README.md / README_zh.md     项目入口(中英)
├── LICENSE / .gitignore / .githooks/ / .github/    许可、忽略规则、钩子、CI
├── pytest.ini / requirements.txt  测试配置;依赖**指针**(真身在内层)
├── tests/                       外层测试(API/页面/守卫)
├── tools/                       工程工具:`setup_all.py`(装新机)、`serve_all.py`(起全部面)、
│                                `make_demo_zip.py`(重打交付包)、`verify_demo_sync.py`(四者比对)、

├── packages/                    两个本地包(mavis-vizkit、mavis-case01-injector)
├── handbook/                   仓库根文档:**框架/对接手册 + 四张录入模板 CSV**(原名 docs/,2026-10-08 改名)
├── logs/                        起面工具的日志(**不是**仿真结果)
├── data/                        ★ 所有"跑出来的存档"的家(不入库;见 §三)
└── provenance/                  ← 内层:**运行面(应用本体)**
    ├── case01/ case00/          两个案例(代码 + 案例资产)

    ├── frontend/ config_tool/   前端与配置工具
    ├── cases/                   场景的**唯一家**:`<case_id>/scenario.yaml`(声明)+
    │                            `<case>/scenario/{story,relationships}.json`(运行期素材)
    └── docs/ results/           内层文档(文档索引在这里)、**算出来的**分析产物
```

**为什么会有这层嵌套(不是历史垃圾)**:`pytest.ini` 把内层放到了 `pythonpath` 上,于是
`from case01... import`、`import case_engine`、`import live` 才能当**顶层模块**用。
一句话:**仓根管"怎么开发/怎么验证",内层管"跑起来是什么"**。内层**不是** Python 包(没有 `__init__.py`)。

> 想扁平化/改名**(尚未做,也不要随手做)**:要改 `pytest.ini` 的 `pythonpath`、根 `requirements.txt`
> 指针、CI、**75 处 `.py` + 80 处 `.md`** 的路径引用、venv 位置,以及**仓外**的 `run_demo.sh`、
> `D:\zzr\_srv\svc_*.cmd` 等脚本。而且代码布局改动**没有回落机制**(漏一处就是导入报错或文件找不到)。

## 七、为什么这里曾经乱(留档,别再犯)

同一个概念("引擎现场存档")曾有三处落点,根因不是"两套设计",而是**一处传参、一处漏传**:

- 实时面起推演时**明确告诉**引擎写到哪(`live/simulation.py` → `results/checkpoints/<模拟名>`);
- 注入器那条路**没传**,而它的桥把 `MAVIS_CHECKPOINTS_ROOT` `setdefault` 成 `<scenario>/checkpoints`
  (`mavis_case01_injector/bridge.py`),mavis 再拼 `<该根>/<模拟名>/storage`
  ⇒ 于是长出 `case01/injector/scenario/checkpoints/`(**85 个模拟埋在场景模板目录里**);
- 第三个 `case01/results/checkpoints/` 是某次没设 `MAVIS_CHECKPOINTS_ROOT` 的运行/测试漏出来的空壳。

已修:注入器起桥前把 `MAVIS_CHECKPOINTS_ROOT` 指到 `data_root("case01.state")`(用引擎自己的开关,
不改那个独立包的公开 API)。**新增数据落点前,先问一句"它属于哪个 kind"**,没有就加一个,别就地发明路径。
