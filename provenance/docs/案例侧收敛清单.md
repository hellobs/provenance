- 0920「场景引擎通用化」把 `case01/injector` 里的机制抽成 `case_engine/`，但 `case01/` 里的**旧实现没有被退役**：

  唯独没有"抽出通用层之后，原处该退的退了吗"这一维。现已补 `tools/deep_check.py` 的 **K 节**。

## 二、逐模块清单

**`case01/consistency.py`（174 行）vs `case_engine/consistency.py`（164 行）**
- 关系：同名同职责，逻辑同源（git diff 仅 89+/98−）；引擎版把词表/说话人/判定器做成了注入点。
- **差异不在文案表**：T0 缺失时的回退行为不同；判定理由字符串不同
  （case01 写"没有 T0…"，引擎写"没有受判主体的对话，无法判断（继续追问）"）。
- 处置：**逻辑归引擎、措辞归案例** —— 给引擎补"判定文案可注入"的小口子，
  case01 把词表（18 个买入词等）、说话人 id（`ai`/`investment_ai`）、`LLMBranchJudge`、理由文案注入进去。
- 验证：`case01/tests/test_consistency.py`（本次尝试时正是它拦下了上面两处差异）。

**`case01/reflection.py`（501 行）vs `case_engine/reflection.py`（438 行）**
- 关系：**函数集完全相同，但除 `_looks_like_meta` 外每一个函数体都不同** —— 不是复制品，是已分叉的两套实现。
- 提示词差异明显：`ROUTER_PROMPT_CN` 882 vs 699 字、`REFLECTION_SYSTEM` 235 vs 141 字、
  `REFLECTION_PROMPT_CN` 956 vs 954 字（`ROUTER_JSON_HINT` / `ROUTER_REWRITE_HINT` 逐字相同）。
- 处置：**逐函数对照合并**（不是替换）：提示词与 `assemble_reflection_material` 的说话人标签留案例侧、
  经 `run_reflection(..., reflection_prompt=..., speaker_labels=...)` 注入；纯函数（strip / parse / rewrite）
  以引擎为准，合并前先逐条比对行为差异。
- 风险：高（改动会直接影响反思正文与 router 问题，属对外可见内容）。

**`case01/orchestrator.py`（573 行）**
- 被 `run.py` **与 `case01/injector/worldfacts.py`** 使用 → 不能按"只被 run 引用"处理。
- 处置：先定"旧 CLI 路径由谁替代"（现入口是 injector/引擎），再退役。

**`case01/run.py`（97 行）、`case01/render.py`（463 行）**
- import 侧 0 引用，**但**它们是 `case01/README.md` 里 `python -m case01.run` / `-m case01.render`
  的文档化 CLI 入口（实测仍可运行）。
- 处置：退役必须**连 README 与文档一起改**，否则文档会指向不存在的入口。

**`case01/viz.py`（357 行）**
- 已被 `vizkit` 取代（`case01_可插拔可视化设计.md` 自述"不再使用已归档的 `python -m case01.viz`"），
  但 `case01/tests/test_viz.py`、`test_vizkit.py` 仍 `from case01 import viz`。
- 处置：把这两个测试改为直接测 `mavis-vizkit`，再删 `viz.py`。

## 三、收敛原则与验证口径

- 原则：**逻辑归引擎，措辞归案例**。引擎不得内置任何案例措辞；
  案例通过参数注入提示词、词表、说话人、判定器（引擎已支持 `reflection_prompt` / `router_prompt` /
  `signals` / `speaker_ids` / `judge_factory`）。
- 验证：`pytest case01/tests case_engine/tests`（498 条）+ 外层 73 条 + `tools/deep_check.py` 的 K 节
  （K 节须从"两套并存"变为"case01 已引用 case_engine"）。
- 顺序建议：`consistency`（先开口子）→ `reflection`（逐函数合并）→ `viz`/`render`（连测试与 README）
  → `run`/`orchestrator`（定替代入口后退役）。

## 四、本轮踩过的坑（避免重犯）

1. 引用检测三错：子串假阳性（`run_naming` 命中 `run`）、漏相对导入与字符串引用
   （`from ..review_app import`、`uvicorn case01.serve:app`）、漏 `from PKG import name`
   （`from case01 import viz`）—— 最后一个导致真的误删模块、测试 collection error（已还原）。
2. 生成本文件类改写时两次事故：占位符未替换（`{BUY}` 变成字面量）、字符串里嵌套引号
   （写 `.py` 补丁脚本时踩到）。结论：**改写一律走 .py 脚本并即时 `ast.parse` 自检**。
3. 收敛尝试必须以测试为准：把 `consistency.py` 换成薄适配层后，
   `test_only_t0_day_is_used...` 与 `test_no_t0_dialogue_reports_unknown...` 立刻失败 ——
   说明两份实现在"边界行为 + 判定文案"上确实不同，**不能当复制品替换**（已回退，498 条恢复全绿）。
