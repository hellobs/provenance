# 数据可得性对照：平台字段 ↔ 取数位置

> **状态**:现行
> **最后核对**:2026-10-09
> **说明**:平台界面上的每个字段在我们这边从哪个接口哪个键取、落在哪个文件、safe 视图裁掉哪些、哪些今天取不到;全部按 2026-10-09 在 5010 实调,逐条可复敲

## 〇、怎么用这张表

- **面向平台的只有一处**：`http://<仿真主机>:5010`。8060 是场景配置面板（另一个进程，不属于对接面），
  落盘文件是作者机取证用的，**平台不要来读文件**（路径/编码/根目录都可能随搬迁变）。
- **本文里 `data.turns[].text` 这种写法是 JSON 路径**，指响应体里的嵌套位置，不是文件路径。
- **`safe`（专家安全视图）是默认**：`/api/run-detail/*` 与 `/api/review/*?safe=1` 都会**白名单裁剪**。
  本表凡是"safe 不给"的键都单独标出，别在平台侧当必有字段用。
- ⚠ **键集不恒定**（实测）：同一接口对不同记录给的键不一样 ——
  `261008-towncheck-5011` 的详情有 `summary` / `compat` / `injector` 三块，而 `probe-router-1008b`
  与批记录 `batch-261008-160333-p61check8b2-001` **一块都没有**；
  `manifest_*` 三键只在 `source=review` 的行上有，`checkpoint`/`compressed` 行压根没这几个键
  （见 §三）。**平台侧渲染请按"键不在就显示『未知』"写，不要按固定列数写死。**

- **称谓**：本表与其余对接文档一律写"平台侧"。"OpenValue" 这个名字在仓内现行文档里只出现在
  《仓库布局说明》一处，**还没定为正式称谓**（定了之后再统一替换，别把它当契约里的字段名读）。

复敲用的三个样本 id（都在本机 10-09 在场）：`probe-router-1008b`、
`batch-261008-160333-p61check8b2-001`（批路径）、`261008-towncheck-5011`（带注入器数据那一路）、
以及有专家意见的任务 `batch-261007-212235-sample8b15-009 / issue-2 / E4`。

## 一、记录级（列表与选择器）

| 平台上的名字 | 取数位置 | safe 给吗 | 注意 |
| --- | --- | --- | --- |

| 数据来源 | `runs[].source` | ✓ | 只有三个值：`review` / `checkpoint` / `compressed`；写别的当路径参数是 404 |

| 起止日期 | `runs[].start_date` / `end_date` | ✓ | 列表按 `end_date` 倒序，空时间的排最后 |
| 轮数 | `runs[].n_turns` | ✓ | |
| 反思条数 | `runs[].n_reflections` | ✓ | |
| 有无图谱 | `runs[].has_graph` | ✓ | |
| **质检结论 `quality`** | `runs[].quality` | ✓ | ⚠ **产物里没有这个字段**：它是读侧从 `consistency` / `branch_action.source` / `deprecated` / `debug` / 反思是否生成**现算**的（`case01/full_context.py:quality_of`）。六个值：`ok` / `unverified` / `questionable` / `debug` / `deprecated` / `unreadable`。**最后一个由 5010 读盘时造**（目录在、`run.json` 不在），不在 `quality_of` 里 |

| 判定方式 | `runs[].branch_source` | ✓（`/api/runs`） | ⚠ 专家面**不该显示**它：九块详情 safe 视图已把它连同 `branch` 裁掉（见 §二） |

| T0 立场一致性 | `runs[].consistency` | ✓（`/api/runs`） | 同上 |
| 作废/调试标记 | `runs[].deprecated` / `debug` / `deprecated_reason` | ✓ | 只有 `review` 源给 |

| 默认视图之外还有多少 | `GET /api/runs` → `excluded.count`（+ `excluded.runs[]` 带 run_id/quality/reason） | ✓ | 10-09 实测：`total=557`、`excluded.count=69`、全库 626 条 |
| 本页条数 vs 总数 | `count` vs `total` | ✓ | ⚠ `count` 是**本页**条数（受 `limit`/`offset`/`source` 影响），`total` 是过滤后总数 |
| 参数有没有生效 | `ignored_params` + `ignored_note` | ✓ | **只在 `/api/runs` 有**这个回显（认识的参数只有 `include_questionable`/`limit`/`offset`/`source`）。别的接口不认某个参数时**不会**告诉你，别拿 `?quality=ok` 去打 `/api/run-detail` |
| 数据源整块跳过 | `source_errors` + `source_errors_note` | ✓ | 看到 `count=0` 先读这里：根目录解析失败是**整块没扫**，不是"这源本来就空" |

`GET /api/review/runs?safe=1`（九块面自己的列表）的列是另一套，只有 10 键：
`run_id / start_date / end_date / engine / n_turns / n_events / n_retrievals / n_issues / has_reflection / quality`；
`safe=0` 才多 `branch` 与 `branch_summary` 两键。同名参数在这一面叫 `hidden_count` + `hidden[]`，不叫 `excluded`。

## 二、单条详情的九块正文

入口只有一个：`GET /api/run-detail/{source}/{run_id}`（默认 safe；`?raw=1` 是内部全文，**不给平台**）。
实测 safe 视图顶层给：`run_id / start_date / end_date / turns / retrievals / events / state_history /
final_feedback / audit / condition_monitor / reflection / router`（+ `_view="expert-safe"`）。

| 页签 | JSON 路径 | 键（实测） | safe 给吗 |
| --- | --- | --- | --- |
| 概览 overview | 上面那一层拼出来 | — | ✓ |
| 对话 turns | `data.turns[]` | `speaker / date / text`；**部分记录另有 `ethan_gen`**（实测批记录 `batch-261008-160333-p61check8b2-001` 与 `probe-router-1008b` 有，`261008-towncheck-5011` 无） | ✓ |
| 检索 retrievals | `data.retrievals[]` | `query / current_date / hits / source_stats`（**带注入器那一路是 `query / date / injected / mode`，没有 `hits`**） | ✓ |
| 事件 events | `data.events[]` | `date / kind / summary / source / price_usd` | ✓ |
| 状态 states | `data.state_history[]` | `date / state{cash_rmb, hcm_shares, held_fraction, entry_price_usd, exit_price_usd, exited}`（⚠ `state.branch` **safe 视图里被剥掉**，raw 与盘上都有） | ✓ |
| 最终反馈 | `data.final_feedback` | `date / ethan / ai` | ✓ |
| 反思 reflection | `data.reflection` | `text / material / quality` | ✓ |
| 问题分流 router | `data.router` | `issues / postprocess / executed_by / expert_pool_version / raw` | ✓ |
| 审计 audit | `data.audit[]` | `t / action / kind / summary` | ✓ |
| 条件监控 | `data.condition_monitor[]` | 可为空数组 | ✓ |
| **注入器 injector** | `data.injector.nodes[]` | `node_id / date / step / released_events / events[]` | ❌ **safe 裁掉**，专家面上这个页签压根不列（`?tab=injector` 给黄条说明） |
| 判定方式/分支 | `data.branch` / `data.branch_action` | — | ❌ safe 裁掉 |
| 一致性 | `data.consistency` | — | ❌ safe 裁掉 |
| 运行设定 | `data.manifest` | 见 §三 | ❌ safe 裁掉（要读它请走 `?raw=1`，内部用） |

另有三块 `summary` / `compat` / `injector` **只在带注入器数据的那一路记录上出现**
（实测 `261008-towncheck-5011` 有，`probe-router-1008b` 与 `batch-261008-160333-p61check8b2-001` 都没有）。
其中 `summary` / `compat` safe 仍给，`injector` safe 不给。

`data.router.issues[]` 实测有 17 个键，含 `id / summary / field / suggested_field / style / risk / risk_note /
routing_reason / expert_category_id / secondary_expert_category_ids / match_status / evidence_status /
evidence_quote / model_evidence_quote / evidence_sentence_ids / invalid_evidence_sentence_ids / merged_from_issue_ids`。

`data.router.issues[]` 的引用口径：证据按**本次反思内的临时句子编号**（`S001`…）给，程序按编号回填
`evidence_quote` 逐字原文；对不上的编号进 `invalid_evidence_sentence_ids`，**不会**静默接受模型改写出来的"伪引用"。
`router.postprocess` 记原始数/过滤数/合并数/截断数/最终数 —— 审计要引它，别把 `merged_from_issue_ids` 当新任务 id。

## 三、记录旁的文件与"这一条怎么跑的"

平台不读文件，但**问我们"这条能复现吗 / 谁跑的"时，答案在这些地方**（根目录都可被环境变量改，见《仓库布局说明》）：

| 想知道的 | 落盘位置 | 谁写 | 读侧注意 |
| --- | --- | --- | --- |
| 正文与九块 | `data/case01/runs/<run_id>/run.json`（另有 `turns.jsonl` / `retrievals.jsonl` / `branch.json`） | 引擎 / 映射 | 10-08 起记录根搬到 `data/case01/runs`；包内 `case01/runs` **已不存在**，照老路径扫永远 0 条 |
| 运行设定 manifest | `run.json` 的 `manifest`（21 键） | 引擎 | 实测三个样本记录都给满 21 键，含 `seed / temperature / judge_model / judge_prompt_version / git_commit / scenario_sha256 / truncations / manifest_warnings / branch_source …` |
| 随机状态（复现档②） | `data/case01/runs/<run_id>/rng.json` | 部分路径写 | ⚠ **实测 `probe-router-1008b` 目录里没有 `rng.json`**，而 `261008-towncheck-5011` 与批记录都有。所以"没有 `rng.json`"不能读成"这条不是同一种跑法"，也不能反推"没播种"（待拍项 #27）。"同种子逐字复现"的口径只在批路径上实测成立 |
| 提示词代次 | `run.json` **顶层** `prompt_flags`（`ai_system_template_sha8` 等） | **10-08 起的批路径写** | ⚠ 它在**顶层、不在 `manifest` 里**；且 safe 视图不给（要 `?raw=1`）。实测三个样本只有 `batch-261008-160333-p61check8b2-001` 有。另：`ai_system_template_sha8` 哈希的是**模板**而不是发出去的正文；改名前那 5 条（`newgen5`）仍带旧键，没回填 |
| 分流/判定的执行身份 | `run.json` 的 `router.executed_by`（`provider/model/host/source`） | 两条路都写，`source` 三词不同 | 默认跑法是 `local_*`（外部 Router API 没配就回落本地），别把"有 executed_by"读成"用了外部模型"。**面板上"Router 后端"那一行取的就是它** |
| Investment AI 提示形态 | `run.json` 顶层 `prompt_flags.ai_reasoning_hint`（布尔） | **10-08 起的批路径写** | **面板上"Investment AI 提示形态"那一行取它**（`review_app.py:652`）。⚠ **键不在时的文案有两种，别混**：带注入器数据那一路记「不适用」（镇内台词不经那份模板），跑在 10-08 之前的记「未记录」 |
| 分支判定过程 | `data/case01/runs/<run_id>/branch.json`（`branch / action{judge, attempts, raw_outputs, c_plan, t0_rounds, source}`） | 引擎 | 判据版本 `2caf63f9…`→`aad4dbe1…`（10-08 换版）：**新旧批的 A/B/C 占比不可并算** |
| 专家意见（训练线材料） | `data/ledgers/reflection_marks.json` + `.jsonl` | `/api/expert/decision` 与 `/api/reflections/mark`（**同一处实现**） | 台账常比磁盘少几条；引用批数前先对账 |
| 干预记录 | `data/ledgers/interventions.json` | 干预分发口 | 10-09 实测这一库 53 条**无一属于 case01**（含 4 条 `../../etc/passwd` 越界探针残留）——别把它当 case01 的治理证据 |
| 旧记录（case00 痕迹） | `results/checkpoints`（`CASE00_CHECKPOINTS_ROOT`） | 沙盒 | 2.31 GB 单副本 |
| 压缩成品 | `results/compressed`（`RESULTS_COMPRESSED_ROOT`） | — | 行上多一个 `incomplete` 键 |
| 训练材料池 | `results/lora/sft.jsonl` / `dpo.jsonl` | `lora_prep --export` | ⚠ **不是实时值**：队列里的 `pool` 文案取的是**上次导出**的结果；今天 `sft/dpo` 都是 0 字节 |
| **批处理台账** | `results/analysis/batch_runs/<批号>/ledger.jsonl`（一行一条） | 批跑脚本 | 行键实测含 `run_id / ok / read_ok / returncode / seconds / ts / seed / branch / consistency / turns / events / issues / issues_final / reflection_{status,score,chars,failure_reasons} / **model_requested** / **model_actual** / attempt / cmd / timeline`。⚠ **模型身份只在这里分得清**（`model_actual` vs `model_requested`），产物 `manifest` 里只有声明值。台账可能比磁盘**少几条** ⇒ 引用前先读同目录 `analysis.json` 的 `ledger_gap*` / `ledger_missing` |
| 批的聚合结论 | `results/analysis/batch_runs/<批号>/analysis.json`（实测 41 份）+ `summary.json` / `summary.md` / 每条 `.log` | `case01/tools/batch_analyze.py` | `analysis.json` 顶层键含 `n_runs / n_unreadable / branches / branch_top / consistency / router / reflection / llm / per_run / ledger_gap{,_detail,_resolved} / ledger_missing / excluded_failed / **runs_root**`。⚠ **`runs_root` 是 10-08 才加的**：早于它的批不记自己扫的是哪个根，跨机复算时对不上 |
| 其它体检产物 | `results/analysis/**`（`branch_judge_eval*` / `reflection_review` / `cases_frozen_*` / `_live_qa_*` 等一次性探针） | 各分析脚本 | 作者机取证，**不是平台字段来源** |

**记录形状不一致（10-09 实测，别按"五件套"写死）**：同一 `data/case01/runs/` 下三种形状并存 ——
批路径 5 个文件（`run.json` + `turns.jsonl` + `retrievals.jsonl` + `branch.json` + `rng.json`）、
`probe-router-1008b` 4 个（无 `rng.json`）、`261008-towncheck-5011` 只有 2 个（`run.json` + `rng.json`）。
所以"某个文件不在"必须先问是哪一路产的记录，再决定是"没记"还是"不适用"（面板那两行就是这么分的，见上表）。

## 四、建单与专家闭环

**先后关系（这条链少了任何一步都会做错账）**：

```
GET /api/expert-categories          拿类别池（Router 只匹配目录内 ID，匹配不到显式标 unmatched）
  → GET /api/review-package/{run_id} 读 data.status：blocked 就别建单（HTTP 仍是 200）
  → GET /api/expert/queue            工作列表（按 state_rank 排；n_opinions 是"几位主体"）
  → GET /api/expert/read?run_id=…    专家读正文（blocked 记录 409）
  → POST /api/expert/decision        提交一份意见（写口；看 training_effect 有没有被门挡）
  → GET /api/expert/marks            回头核对：这一任务现在算几份
```

| 平台上的名字 | 取数位置 | 注意 |
| --- | --- | --- |
| 建单候选 | `GET /api/review-package/{run_id}` → `data.task_candidates[]` | 每条含 `key`（`[source, run_id, issue_id, category]`）/ `issue_id` / `expert_category_id` / `summary` / `risk` / `routing_reason` / `evidence_quote` / `evidence_sentence_ids[]` |
| **这局能不能建单** | `data.status`（+ `data.blocked_reasons[]`） | ⚠ **HTTP 一律 200**，不合格记录也是 200 而 `task_candidates` 为空。**必须读 `data.status`**，四个原因码是字面量 |
| 人工分流 | `data.manual_triage[]` | 非空就说明有样本 Router 没跑成，不是"没问题" |
| 正文全文（自然语言） | `data.full_context` | |
| 类别池 | `data.expert_categories[]` + `data.expert_pool_version` | 同一份也在 `GET /api/expert-categories`（`version / name / description / categories[]`，类别含 `id / name / description / aliases / keywords`）。**只含类别**；具体专家人员与可用状态归治理平台 |
| 版本戳 | `data.record_revision` / `category_revision` / `revision`，`schema_version` | |
| 归属约定 | `data.ownership.tasks` / `.reviews` | |
| 工作队列 | `GET /api/expert/queue?limit=N` → `tasks[]` | 键名是 **`tasks`**（不是 `items`）。每条：`run_id / issue_id / expert_category_id / summary / risk / routing_reason / evidence_quote / anchor{sentence_ids, quote} / n_opinions / review_state / state_rank / pool{state, n_rows, rejected_reasons}`；顶层还有 `n_runs_scanned / n_tasks / n_manual_triage / n_blocked / manual_triage / blocked / verdict_words / pool_generated_at / opinions_counted / excluded / counting_rule / note` |
| 审核状态词 | `tasks[].review_state`（+ `state_rank`） | 排序是 0 Disputed > 1 争议轮 > 2 等第二份 > 3 待领取 > 4 首轮已齐，同档内高风险在前 |
| **`n_opinions` 的口径** | 同上 | ⚠ **是"几位主体已交"，不是"盘上有几行"**：一份 = 一个 `review.expert_ref` 在该任务上的最新版本，且 `origin` 为 `expert`（缺 `origin` 按 expert 算）。不计数的三类在顶层 `excluded{no_coordinates, non_expert_origin, superseded}` 里报数，口径随 `counting_rule` 一起发。平台按行数算会比我方面板**多报** |
| 专家要读的正文 | `GET /api/expert/read?run_id=<id>` | ⚠ **`run_id` 是查询参数**，且是**按记录**取不是按任务取。返回 `reflection_text / reflection_chars / full_context / categories`；记录非法 400、不存在 404、交接包 `blocked` 时 **409 且不给空正文** |
| 已交意见计数 | `GET /api/expert/marks` | `total`（盘上行数）/ `with_review_block` / `opinions_counted` / `excluded` / `by_category` / `opinions_per_task`（键是 `run_id|issue_id|category` **拼串**）/ `tasks_with_two_or_more` / `tasks_disputed` / `visibility`。**只给条数，不含结论与文本**（首轮两份互不可见）；这不等于受保护 —— 5010 无鉴权，知道 run_id 的人仍能从标记文件读到内容 |
| 提交一份意见 | `POST /api/expert/decision` | ⚠ **写口**：直接落训练线台账。`expert_id`/`operator`/`origin` 等键客户端**不许**指定（丢弃并记 `dropped_client_keys`）；主体取服务端观测到的连接方地址。返回里 `training_effect` 当场说明这份进训练集会取哪份文本、被哪道门挡。**只读代理要把它按 §八（嵌入手册）挡在写侧** |

10-09 在这一库上的实测：`total=6 → opinions_counted=3`，`excluded = 2 / 1 / 0`，`tasks_with_two_or_more=0`；
队列 `n_tasks=63`（等第二份 3 / 待领取 60），`n_manual_triage=1`。

## 五、取不到的（别在平台侧留字段占位）

| 平台想显示的 | 现状 | 该怎么办 |

## 六、同名不同值的坑（逐接口实测，别类推）

1. **`include_questionable` 在各面不等价**：`/api/runs` 认（`filter.include_questionable` 回显）；
   `/api/review/runs` 曾**静默失灵**，10-09 修好（`a882ef4`），现回显同名 filter 并把隐藏项数在 `hidden_count`；
   `/api/run-detail` **不认**，而且**不会**给 `ignored_params`（那回显只在 `/api/runs`）。
2. **两套"隐藏了多少"**：`/api/runs` 叫 `excluded{count, runs[]}`；`/api/review/runs?safe=1` 叫 `hidden_count` + `hidden[]`。
3. **队列的键是 `tasks`，不是 `items`**；**交接包的问题在 `data.task_candidates`，不是 `router.issues`**（顶层没有 `issues`）。
4. **三栏（`manifest_*`）只在 `source=review` 的行上**；`checkpoint` 行少 `manifest_*`/`deprecated`/`reason`，`compressed` 行还多一个 `incomplete`。
5. **`quality` 有六值而 `unreadable` 不由 `quality_of` 造**：它是 5010 读盘时补的（目录在、`run.json` 不在）。
6. **`safe` 的裁剪幅度按接口、也按记录不同**（10-09 实测 raw 减 safe 的顶层键差集）：
   `probe-router-1008b` = `branch / branch_action / consistency / manifest`；
   `batch-261008-160333-p61check8b2-001` 多一项 `prompt_flags`；
   `261008-towncheck-5011` 多 `debug / injector`（而它的 `summary` / `compat` **safe 照给**）。
   列表（`/api/review/runs`）只裁 `branch / branch_summary` 两键。
   ⚠ 还有一处**嵌套**裁剪：`state_history[].state.branch` 在 safe 里被剥掉，raw 与盘上都有。
7. **`run-detail` 的 `source` 是路径白名单**（`review` / `checkpoint` / `compressed`），写别的 404。
8. **`/health` 的 `run_id` 是"画布上现在这一局"**，不是"最近一条成品记录"；只审阅模式下它是空串（实测 `run_id=""`、`finish_reason="review_only"`、`restart_ready=false`）。区分在推演/已跑完/仅审阅要靠 `finished` + `finish_reason`，别靠画面猜。
