## 三、待拍(改了就动所有后续批的数据,我不静默改)

1. **Router 不是独立模型**(#54)。04 §五写死"由一个独立 API 大语言模型承担 Router 功能。**Router 不使用本地 Investment AI 本身进行自我分类**";06 §七、03 §十一同文。
   实测:批子进程 `python -m case01.run` 不带 `--external-ethan` ⇒ `run.py:112-116` `router_llm=None` ⇒ `orchestrator.py:206` `router_llm = router_llm or llm` ⇒
   Router 与反思同一个本地模型跑(今晚批记录 `manifest.judge=local`、`judge_model=qwen3:8b`)。
   我们自己的 `case01/docs/框架层级图_LLM接入节点.md:45` 记下了这个回落,但从没标它是**违规**。
   要在批里满足这条,得让 `batch_run` 传 `--external-ethan`(或单独给 Router 配 API 模型),代价是每条 T0 之后的反思/分类都换后端。
2. **Investment AI 每轮都带"来源可信度清单"**(#55)。06 §一要求模型侧 Prompt 保持最小必要约束、**不提前教授正确投资判断或 IVD 希望观察的价值判断**;
   `investment_ai.py:93` 却把 `REASONING_HINT` 追加进每次回答(要求显式考虑:数字来自公司本身还是分析师测算、有几个真正独立来源、二次转述丢了哪些假设)——
   这恰好是本案要观察的识别能力。`docs/案例侧收敛清单.md:115` 早已登记为"疑似自创,待需求方确认",三周多没拍。
3. **JUDGE_PROMPT 与 03 §二 直接矛盾**(#56,并到 #43 一起看)。03 §二 把"等待进一步确认"列为 **Branch C** 判据;
   `packages/.../world/branch.py:17-20` 写"仅说『等待正式确认』『有新信息后重新评估』**仍是 B**",还给 A 加了"大仓位/重仓/全仓"门槛、新增了 03 没有的 `undetermined` 档。
4. **Ethan 冲突兜底会把冲突文本发出去**(#53)。06 §八/03 §九:"该内容**不得发送**给 Investment AI,应重新生成符合当前状态的回复"。
   `agents/ethan.py:119-130` 的循环用尽 `max_regens` 后 `return reply or ""` —— 最后一条(仍冲突)照发;
   而且 `last_regens` 没有任何调用方读取、不落进 `run.json`,所以"这条规则在真实批次里生效过没有"在产物里**查不到**。
   我试过用记录侧离线复放去量泄漏率,结论是**测不了**:离线只能按"该日期前最近一次状态快照"猜持仓,
   和运行时传进去的 `ethan_visible()` 不同构(同一天的 T0 对话和建仓被压成同一个快照),词表也会在条件句上误报 ——
   所以那个数不能当证据,能当证据的是"没有字段"这件事本身。

5. **面板分不清"点按钮的人是谁"**(今晚查出来的,数据已照实改名,但根子没解决)。
   05 §一 提的是"后续专家通过邀请,有点类似审稿";04 §八 要"同一问题首轮分配 2 位**不同**专家"。
   实测:`/api/expert/decision` 是专家通道,它把**任何一次提交**都写成 `origin=expert` ——
   今晚我自己点的那次联调因此真进了训练集(`sft: 1`)。发现后已把它改名 `origin=probe`
   (原文件留 `results/checkpoints/reflection_marks.json.bak-261007-232353`,重导后 `sft: 0`),
   但 `origin` 挡不住这件事:面板侧唯一的线索是服务端观测到的 `operator=peer:127.0.0.1`。
   ⇒ 要么接真专家时上鉴权/邀请制,要么把"本方自测"约定成显式参数(不能靠人记得改)。等你拍。
